Ongoing Submitted 2026-08-06 Last comment 2026-08-11 memcg stats flushing (WAS "Re: [PATCH] fuse: disable default bdi strictlimiting") Needs Work LLM (per-reviewer) Changes Requested

This patch addresses the issue of stale memory cgroup (memcg) stats causing premature OOM kills by proposing a solution to reduce the overhead of updating and flushing these statistics. The idea is for memcg to accumulate updates on a per-CPU basis, then propagate them up to a global atomic counter when it reaches a certain threshold, eliminating the need for frequent flushing. This approach aims to scale better for large machines with many cores and focuses on reducing the number of stats that require flushing, specifically NR_FILE_DIRTY and NR_WRITEBACK in the writeback case.

[RFC PATCH] mm/cma: don't release CMA pages still in use Neutral LLM RFC

This RFC patch proposes a fix for a double-queue bug in the CMA (Contiguous Memory Allocator) code, which can lead to corruption of buddy lists and memory leaks. The patch introduces a new function __cma_release_frozen() that frees already-frozen pages in contiguous runs while skipping still-referenced pages. This change aims to prevent the CMA address space from being leaked when pages are still in use.

Ongoing Submitted 2026-07-31 🔥 TODAY [PATCH] futex: Avoid hash-bucket locking for mismatched waits Needs Work LLM (per-reviewer) Under Review

This patch modifies the futex_wait_setup function to read the futex word before taking the hash bucket lock, reducing contention and improving performance. The change allows for a precheck of the futex value without acquiring the lock, which is particularly beneficial in scenarios where the futex words are frequently mismatched. This approach also simplifies the code by removing unnecessary lock acquisitions and waiter accounting operations. By avoiding hash-bucket locking for mismatched waits, the patch aims to reduce contention and improve overall system performance.

Ongoing Submitted 2026-08-07 🔥 TODAY [PATCH v2] squashfs: avoid thundering-herd cache wakeups Needs Work LLM (per-reviewer) Accepted

This patch modifies the squashfs cache handling to avoid 'thundering herd' wakeups, which occur when multiple tasks are woken up simultaneously due to a single event. The patch makes waits exclusive and enqueues them while holding the cache lock, ensuring that a concurrent lookup either sees the waiter queued or the waiter sees the block published. This change reduces CPU usage spikes caused by frequent wakeups and improves system performance.
