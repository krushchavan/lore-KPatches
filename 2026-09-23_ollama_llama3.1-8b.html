Ongoing Submitted 2026-09-14 🔥 TODAY [PATCH] mm/page_alloc: let the bulk and folio allocators carry alloc_flags Needs Work LLM (per-reviewer) Under Review

This patch allows the bulk and folio allocators to carry allocation flags, enabling callers to select allocator behavior such as an alternate zonelist. The change adds new entry points in page_alloc.h that take an explicit alloc_flags parameter, matching the existing __alloc_pages_noprof() function. This modification does not introduce any functional changes, as all current callers pass ALLOC_DEFAULT. The patch is a preparatory step to address potential conflicts with other ongoing work on allocation flags.

This patch refactors the zonelist constructors and iterators in the Linux kernel to make them more flexible and modular. It introduces a new function `find_next_best_node_in` that takes an explicit candidate set, allowing callers to narrow down the selection of nodes. Additionally, it extracts a per-node construction loop from `build_zonelists` into a separate function `build_node_zonelist`, parameterized on the candidate nodemask and destination zonelist index. This patch renames a local variable in the alloc_pages_bulk_noprof function to clarify its scope and purpose. The variable, previously named alloc_flags, is used for fast-path watermark, cpuset, and CMA decisions, which are distinct from the allocator behavior flags stored in the alloc_context. The renaming does not change the functionality of the code, but improves clarity by distinguishing between these two types of flags.
