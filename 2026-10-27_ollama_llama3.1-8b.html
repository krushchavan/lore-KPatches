Ongoing Submitted 2026-10-24 🔥 TODAY [PATCH] mm/mempolicy: recompute automatic interleave weights on memory hotplug Needs Work LLM (per-reviewer) Under Review

This patch updates the automatic interleave weights in Linux's memory policy when a node gains or loses memory due to hotplug events. The current implementation only recalculates the weights when a new bandwidth is reported, which can lead to incorrect weights being used for some nodes. This patch introduces a new function `wi_state_refresh` that recomputes the weights from the recorded bandwidth whenever a node gains its first memory or loses its last. This ensures that the weighted interleave algorithm always uses accurate and up-to-date weights, leading to improved performance in certain scenarios.

Needs Work LLM (per-reviewer) Under Review

This patch series addresses six races in the Linux kernel's memory management code that can cause crashes or incorrect behavior when memory is offline. The patches introduce a new function, pfn_walk, which waits for pending page walkers before poisoning the memory map, and modify various functions to use this new function or hold get_online_mems() instead. This ensures that memory is not accessed after it has been marked as offline, preventing crashes and incorrect behavior. The changes are tested on a QEMU guest with three NUMA nodes and a pc-dimm left offline at boot, and the results show that the patches fix all six races without introducing any significant performance cost.

🔥 TODAY Re: [PATCH 25/46] mm/userfaultfd: wake waiters when registration modes are removed Reviewed-by Needs Work LLM (per-reviewer) Under Review

This patch fixes an issue where the userfaultfd registration mode is not properly updated when changing from MISSING|WP to WP, leading to missing pages still waiting for userspace access. To fix this, the patch changes the comparison logic in userfaultfd_register_range() to ensure that the current and requested UFFD modes match exactly before skipping the update. This change is necessary to prevent writers from timing out due to missing faults.

Needs Work LLM (per-reviewer) Accepted

This patch reduces cacheline contention between lruvec stat updates and LRU lists by rearranging the layout of struct mem_cgroup_per_node to pair read-mostly lines with cold lines, and modifying folio and kmem stat updates to avoid going through the lruvec. This change improves performance on systems that use spatial prefetching, such as Intel CPUs. The patch includes two changes: one that reorders the fields in struct mem_cgroup_per_node, and another that modifies the stat update functions to skip using the lruvec. The results show a significant improvement in pages per second for threads faulting in and freeing memory in a single memcg.
