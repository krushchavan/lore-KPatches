Last comment 2026-10-14 [PATCH v1] mm: unqueue deferred split folios outside the lruvec lock Neutral LLM (per-reviewer) Under Review

This patch modifies the Linux kernel to unqueue deferred split folios outside of the lruvec lock, which is held during certain memory management operations. The change introduces a new function, folio_batch_unqueue_deferred_split(), that can be used in these paths to release the folios from the deferred split queue after the lruvec lock has been released but before they are uncharged. This helps reduce contention and shortens critical sections with IRQs disabled.

Ongoing Submitted 2026-10-09 🔥 TODAY [PATCH v3] mm: page_alloc: make defrag_mode retries follow the promoted order v1 → v2 → v3 Needs Work LLM (per-reviewer) Under Review

This patch modifies the page allocation mechanism in Linux to make defragmentation mode retries follow the promoted order of requests, rather than the original request order. This change aims to prevent indefinite retrying by order-0 requests and reduce memory pressure caused by frequent direct reclaim runs. The promoted order is computed once per iteration and passed to relevant functions, ensuring consistency across different callers. Additionally, the patch resets retry counters when a promoted request takes the fallback path, allowing for a full retry budget before OOM killing is considered.

🔥 TODAY Re: [PATCH v3] mm: page_alloc: make defrag_mode retries follow the promoted order Neutral LLM (per-reviewer) Under Review

This patch modifies the behavior of page allocation in defrag_mode to make retry decisions follow the promoted order, rather than the original request order. This change is intended to prevent a situation where an order-0 request can retry indefinitely without reaching the ALLOC_NOFRAGMENT fallback. The patch also makes adjustments for promoted requests, ensuring that they do not reset no_progress_loops and allowing them to fall back to the fallback attempt with a full retry budget. The goal of this change is to reduce memory pressure and prevent OOM killing in certain workloads.

  • [3/3] mm: zswap: use stack requests for synchronous decompression 🔥 TODAYPositiveUnder Review Yosry Ahmed
Needs Work LLM (per-reviewer) Under Review

This patch series reduces contention on loads in the zswap compression algorithm by introducing separate requests and mutexes for compression and decompression, allowing loads to no longer wait for stores. The patches also enforce a maximum request size for synchronous compression transforms and use an on-stack request for synchronous decompression, reducing lock contention. This results in significant performance improvements, with read times reduced from 22.3ms to 0.97ms on a single vCPU and from 314ms to 7.0ms on 8 vCPUs.

[PATCH] x86/lib: Use REP MOVSB for large memcpy() on ERMS CPUs without FSRM Neutral llm-chunked-no-replies Awaiting Review

This patch optimizes the memcpy() function on x86 CPUs without FSRM (Fast String Replication Mode) but with ERMS (Enhanced REP MOVSB). It selects REP MOVSB for large copies (512 bytes and above), which is faster than the original implementation, and keeps the original implementation for smaller copies. This change improves performance in scenarios like btrfs/zstd decompression, where memcpy() is a bottleneck.
