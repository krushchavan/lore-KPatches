Needs Work LLM (per-reviewer) Accepted

This patch addresses a performance regression in the Linux kernel, specifically related to swap I/O operations on synchronous devices like NVMe partitions. The issue arises from two commits: one that prefers non-full clusters over free ones and another that frees swap slots on exclusive write faults. This leads to scattered writes and increased read requests, resulting in decreased throughput. The patch proposes a solution by only preferring non-full clusters on synchronous devices, which improves performance metrics such as device read and write requests per transaction and throughput.

Ongoing Submitted 2026-11-09 🔥 TODAY [PATCH v1] mm/rmap: fix migration entries being treated as partial unmaps Needs Work LLM (per-reviewer) Superseded

This patch fixes an issue where migration entries in the Linux kernel are being treated as partial unmaps, leading to incorrect behavior such as unnecessary folio splits and overcounting of split_deferred statistics. The problem occurs when a large anonymous folio is migrated or split, causing the PG_partially_mapped flag to be set even though no actual unmapping has taken place. To fix this, the patch introduces a new flag that prevents __folio_remove_rmap() from marking a folio as partially mapped when migration entries are replaced for PTEs. This ensures that only actual unmappings trigger the deferred split queue and corrects the statistics. The patch also addresses issues related to migrated folios being queued for unnecessary splits and overcounting of split_deferred statistics.

[PATCH v2] mm/page_alloc: only skip kswapd nodes below their kswapd watermark Neutral llm-chunked-no-replies Awaiting Review

This patch modifies the page allocation logic to only skip nodes with active kswapd if they are also below their target watermark. This change addresses a problem where high-order requests would wake up kswapd, causing it to stay awake and allocate pages from other nodes even when there was plenty of free memory on the original node. The patch aims to prevent this thrashing by only skipping nodes that are both under kswapd's control and have insufficient memory. This change is based on observations of Meta production workloads running on 2-NUMA systems, where processes would continuously allocate pages from a preferred node despite having hundreds of GB of free memory. The patch has been tested to show improved allocation behavior, with 100% of pages being served from the preferred node after applying the fix.

This patch series proposes a change to how Linux handles page cache reads, allowing multiple CPUs to read from the same folio without taking a reference. This is done by introducing a new flag PG_rcu_free and deferring the freeing of folios until an RCU grace period. The goal is to reduce contention between readers and improve performance in scenarios where many threads are reading the same pages. The patch series includes 18 patches that implement this change, including modifications to filemap_read(), shmem, and other related functions.

🔥 TODAY [PATCH] btrfs: keep a logged extent allocated when its ordered extent fails Neutral LLM (per-reviewer) Under Review

This patch prevents a logged extent in Btrfs from being freed when its ordered extent fails, which can lead to data corruption and checksum errors during log replay after a transaction abort. The fix involves not freeing the extent of a failed ordered extent that was logged by a fast fsync, but instead keeping it out of the free space cache until the next mount. This ensures that the log replay points to the correct blocks with the correct checksums. The patch also includes additional checks and error handling to prevent similar issues from occurring in other scenarios.
