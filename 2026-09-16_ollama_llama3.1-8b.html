Last comment 2026-09-17 [PATCH] btrfs: keep unused block groups queued when a pass fails Needs Work LLM (per-reviewer) Under Review

This patch addresses a potential issue in the btrfs file system where unused block groups can be leaked and lead to spurious ENOSPC errors. The problem occurs when an error is encountered while deleting unused block groups, causing them to be skipped and not re-queued for later processing. To fix this, the patch changes the logic of the deletion loop to break out of it when an error is encountered, rather than skipping the rest of the block groups. Additionally, it links the failing block group to a retry list at the individual failure sites, ensuring that it is not leaked.

Ongoing Submitted 2026-09-12 🔥 TODAY [PATCH] mm/madvise: reclaim isolated folios if PTE restart fails Needs Work LLM (per-reviewer) Under Review

This patch addresses a concurrency issue in the Linux kernel's madvise functionality. When MADV_PAGEOUT is used to collect isolated folios, a concurrent operation can remove or replace the PTE table while the lock is dropped, causing pte_offset_map_lock() to return NULL and bypassing reclaim_pages(). The patch routes this failure through the existing cleanup path, ensuring that any collected folios are reclaimed or put back. This fix prevents a situation where isolated folios remain off the LRU with elevated references.

Needs Work LLM (per-reviewer) Under Review

This patch refactors the zonelist constructors and iterators in the Linux kernel to make them more flexible and modular. The existing behavior of picking nodes from N_MEMORY is made explicit, allowing callers to narrow the set of nodes used for fallback lists. A new function find_next_best_node_in() takes a candidate set as an argument, making it easier to build zonelists over specific sets of nodes. Additionally, the per-node construction loop in build_zonelists() is extracted into a separate function build_node_zonelist(), which can be parameterized on the candidate nodemask and destination zonelist index. These changes enable more flexible and efficient management of zonelists, particularly for generating private node zonelists.

Needs Work LLM (per-reviewer) Under Review

This patch series addresses an issue where special PMDs (Page Map Directory entries) are being treated as regular PMDs, leading to incorrect behavior when accessing the folio behind them. The problem arises from two page table walkers that resolve the folio using pmd_folio(), which is only valid for a PMD mapping a refcounted struct page. This patch series modifies these walkers to use vm_normal_folio() instead, ensuring consistency with the PTE halves of both walkers. As a result, mbind(MPOL_MF_STRICT) over a PMD mapped VM_PFNMAP region now returns 0 rather than -EIO.
