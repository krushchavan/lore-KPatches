Last comment 2026-09-17 [PATCH] btrfs: keep unused block groups queued when a pass fails Needs Work LLM (per-reviewer) Under Review

This patch addresses a potential issue in the btrfs file system where unused block groups can be leaked and lead to spurious ENOSPC errors. The problem occurs when an error is encountered while deleting unused block groups, causing them to be skipped and not re-queued for later processing. To fix this, the patch changes the logic of the deletion loop to break out of it when an error is encountered, rather than skipping the rest of the block groups. Additionally, it links the failing block group to a retry list at the individual failure sites, ensuring that it is not leaked.

Ongoing Submitted 2026-09-12 🔥 TODAY [PATCH] mm/madvise: reclaim isolated folios if PTE restart fails Needs Work LLM (per-reviewer) Under Review

This patch addresses a concurrency issue in the Linux kernel's madvise functionality. When MADV_PAGEOUT is used to collect isolated folios, a concurrent operation can remove or replace the PTE table while the lock is dropped, causing pte_offset_map_lock() to return NULL and bypassing reclaim_pages(). The patch routes this failure through the existing cleanup path, ensuring that any collected folios are reclaimed or put back. This fix prevents a situation where isolated folios remain off the LRU with elevated references.

This patch series addresses an issue where special PMDs (Page Map Directory entries) are being treated as regular PMDs, leading to incorrect behavior when accessing the folio behind them. The problem arises from two page table walkers that resolve the folio using pmd_folio(), which is only valid for a PMD mapping a refcounted struct page. This patch series modifies these walkers to use vm_normal_folio() instead, ensuring consistency with the PTE halves of both walkers. As a result, mbind(MPOL_MF_STRICT) over a PMD mapped VM_PFNMAP region now returns 0 rather than -EIO.

[PATCH v2] fuse: enable large folios Neutral llm-chunked-no-replies Awaiting Review

This patch enables large folios in the FUSE (Filesystem in Userspace) kernel module. Large folios are a way to allocate memory in larger chunks, which can improve performance by reducing the number of requests made to the underlying storage device. The patch caps the maximum order at the largest request that FUSE can issue, ensuring that each folio fits within a single request. This approach allows the allocator to fall back to smaller folios under memory pressure. Benchmarks show significant improvements in read and write performance for both tmpfs backing and xfs on NVMe backing.

This patch modifies the rmqueue_buddy function in the Linux kernel's page allocation code to avoid direct compaction for costly __GFP_NORETRY allocations. The patch corrects an issue where non-blocking allocations were being allowed access to HIGHATOMIC reserves, which can lead to performance problems and incorrect behavior. It introduces a new flag combination ALLOC_MASK_ATOMIC to represent atomic allocations, and updates the rmqueue_buddy function to use this flag correctly. This change ensures that only true atomic allocations are granted access to HIGHATOMIC reserves, preventing potential issues with other types of non-blocking allocations.

Needs Work LLM (per-reviewer) RFC

This patch set introduces sub-folio dirty tracking for PTE-mapped mmap writes, addressing the issue of large page cache folios being dirtied unnecessarily when a single byte is written through a shared file mapping. The problem arises because current implementations mark the entire folio as dirty, leading to inefficient writeback and increased minor fault counts. To solve this, the patch harvests hardware PTE dirty bits at page_mkwrite() time and provides the filesystem with the ranges that were actually modified, allowing for more targeted writeback. This approach is already implemented in XFS and is shown to reduce writeback by 99% on a large file system.

The current implementation has a dedicated linker section for decrypted data, but this only provides page isolation and not shared mapping as intended. The patch proposes creating boundary symbols for the per-CPU decrypted section, an early conversion primitive that works across different encryption technologies, and a single conversion of both sections at boot time.
