🔥 TODAY [PATCH] NFSD: Reject a COPY whose source and destination are the same file Positive LLM Accepted

This patch addresses a requirement in RFC 7862 that the NFSD server must reject COPY operations where the source and destination files are the same, regardless of range overlap. The existing code only checks for overlapping ranges, which is also required by CLONE operations. The patch adds a check to nfsd4_setup_intra_ssc() to verify if the source and destination file handles refer to the same file.

This patch series modifies the Linux kernel to read memory cgroup (memcg) statistics from global counters instead of flushing them, which is expensive and can lead to stale stats. The root memcg's stats are updated directly from global counters, eliminating the need for flushing in most cases. However, three remaining flushes will be addressed in a subsequent patchset. This change improves performance by reducing the time it takes to read memcg statistics, especially on systems with many CPUs and active memory allocation.

🔥 TODAY [PATCH] drm/i915/gem: Skip writeback of shmem folios with extra references Needs Work LLM (per-reviewer) Under Review

This patch modifies the drm/i915/gem module to skip writeback of shmem folios that have extra references, preventing a race condition where a stale TLB entry can still store data to an unmapped folio until the TLB is flushed. The change ensures that such folios are left to reclaim as mapped ones would be, rather than being written back from swap without the stored data.

Last comment 2026-11-20 [PATCH] mm/memory: don't map hardware-poisoned pages in finish_fault() Positive LLM (per-reviewer) Under Review

This patch prevents hardware-poisoned pages from being mapped in the page cache when a large file folio cannot be split by memory_failure(). Instead, it maps each poisoned page individually, allowing it to take its own fault and resulting in a SIGBUS signal. This change addresses an issue where a process touching a poisoned page would instead receive a machine check. The patch builds upon existing functionality in finish_fault() and is designed to prevent the mapping of hardware-poisoned pages when using large file folios.

  • [3/3] mm: vmscan: tell direct reclaim the allocation is ALLOC_NOFRAGMENT Submitted 2026-11-16
Needs Work LLM (per-reviewer) Under Review

This patch series addresses a performance issue caused by the high-order watermark check not honouring the ALLOC_NOFRAGMENT flag in memory pressure situations. The check currently counts free pages of every migratetype, leading to incorrect results and stalls in compaction. The patches modify the watermark checks to take into account the request's migratetype and skip free lists that cannot be used. This is achieved by passing the alloc_flags to try_to_free_pages() and modifying the should_reclaim_retry() function. The changes are based on a benchmark that shows significant improvements in performance, with 64K mTHP faults under memory pressure stalling 18 times less often than without the patch series.

Last comment 2026-11-20 Re: [PATCH v2 00/39] arm64: Add support for FEAT_NMI Needs Work LLM (per-reviewer) Under Review

This patch series adds support for FEAT_NMI (NMI) feature on arm64 architecture. The problem it solves is a race condition where a CPU entering power-down idle state masks SDEI, causing other CPUs to hang in csd_lock_wait() when trying to send an interrupt. The approach taken is to either fix the firmware or modify the kernel to never signal a CPU with SDEI masked, by adding a handshake between the signalling CPU and the cpu_pm notifier.
