🔥 TODAY [PATCH] btrfs: fix block group ref leak when scrub races with unused bg deletion Positive LLM Under Review

This patch fixes a block group reference leak in Btrfs when scrub operations race with unused block group deletion. The issue arises from concurrent access to the `unused_bgs` list, where a block group can be added back to it after being removed. To fix this, the patch introduces a check for an empty list before taking a new reference on the block group.

Ongoing Submitted 2026-11-09 🔥 TODAY [PATCH v1] mm/rmap: fix migration entries being treated as partial unmaps Needs Work LLM (per-reviewer) Superseded

This patch fixes an issue where migration entries in the Linux kernel are being treated as partial unmaps, leading to incorrect behavior such as unnecessary folio splits and overcounting of split_deferred statistics. The problem occurs when a large anonymous folio is migrated or split, causing the PG_partially_mapped flag to be set even though no actual unmapping has taken place. To fix this, the patch introduces a new flag that prevents __folio_remove_rmap() from marking a folio as partially mapped when migration entries are replaced for PTEs. This ensures that only actual unmappings trigger the deferred split queue and corrects the statistics. The patch also addresses issues related to migrated folios being queued for unnecessary splits and overcounting of split_deferred statistics.

[PATCH v3] mm/page_alloc: only skip kswapd nodes below their kswapd watermark v2 → v3 Neutral llm-chunked-no-replies Awaiting Review

This patch modifies the behavior of get_page_from_freelist() to only skip nodes with kswapd running if they are below their relevant low-memory watermark. This change addresses a problem where high-order allocation failures would wake up kswapd and direct order-0 allocations to the fallback path, even when there is free space on the node. The patch was tested on 2-NUMA Meta production workloads and showed improved performance by reducing unnecessary pressure on remote nodes. The change only affects nodes that are under their low-memory watermark, ensuring that kswapd is not unnecessarily woken up.

Ongoing Submitted 2026-11-11 🔥 TODAY [PATCH v3] mm/memory: refuse to map page cache folios that are not uptodate v1 → v2 → v3 Positive LLM (per-reviewer) Under Review

This patch prevents mapping page cache folios that are not up-to-date, which can leak stale memory to userspace. It adds a new function `file_folio_not_uptodate` to check if a folio is uptodate and refuses the mapping in `__do_fault` and `do_set_pmd`. The fault gets a SIGBUS signal for non-uptodate folios, and MADV_COLLAPSE fails and leaves the range to be faulted in. This patch addresses a problem where some filesystems clear PG_uptodate on cached folios, which is considered buggy.

This patch series proposes a change to how Linux handles page cache reads, allowing multiple CPUs to read from the same folio without taking a reference. This is done by introducing a new flag PG_rcu_free and deferring the freeing of folios until an RCU grace period. The patch series includes 18 patches that implement this change, including modifications to filemap_read(), shmem, and other related functions.

Contentious LLM (per-reviewer) Accepted

This patch series removes the 'pipe buffer stealing' feature, which allows a consumer of a pipe to take its page instead of copying the data. The feature was used by fuse and virtio_console, but it has caused issues and required multiple fixes. The patch replaces this behavior with a copy operation when stealing fails, and removes the related code. This change is expected to improve the stability and maintainability of the kernel.
