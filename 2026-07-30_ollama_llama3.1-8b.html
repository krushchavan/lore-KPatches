Last comment 2026-07-31 [PATCH v2] btrfs: flush the fixup workers during close_ctree v1 → v2 Needs Work LLM (per-reviewer) Under Review

This patch fixes a bug in Btrfs where fixup workers can still be running when the fs roots are freed during unmount, leading to memory allocation errors and potential crashes. To solve this, the patch adds explicit flushing of the fixup workqueue before unmount, and also denies new fixup queueing during umount. This ensures that all fixup writeback is completed before declaring BTRFS_FS_STATE_NO_DELAYED_IPUT.

This patch series converts the iomap code to use an in-iter model for iomap_next(), which is a more efficient and scalable approach. The first patch addresses a bug where the folio batch was not being released in certain error scenarios, ensuring that resources are properly cleaned up even when errors occur during I/O operations. The rest of the patches make various changes to support the new in-iter model, including updating functions like iomap_iter() and iomap_next(). This change is expected to improve performance and reduce memory usage for applications using iomap.

Last comment 2026-07-31 Re: [PATCH v1 2/2] mm/memory: add anonymous mTHP folios to deferred split list Needs Work LLM (per-reviewer) Under Review

This patch adds anonymous memory huge page (mTHP) folios to the deferred split list in the Linux kernel's mm/memory module. The goal is to improve the efficiency of scanning for unscanned THPs, which are a problem due to their dynamic nature and the large number of irrelevant pages included in the search pool. The patch proposes an extension to existing refcount checks using the in_deferred_cache(folio) function, rather than introducing more complex solutions such as shared lists or split queues. However, the author acknowledges that hard data is needed to justify the engineering tradeoff and make a proper cost-benefit analysis.
