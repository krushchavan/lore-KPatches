Ongoing Submitted 2026-10-07 🔥 TODAY [PATCH v3] mm: bypass swap readahead for zswap Needs Work LLM (per-reviewer) Under Review

This patch bypasses swap readahead for zswap, an in-memory synchronous backend similar to zram. The current implementation of swap readahead can lead to pointless prefetching of pages, causing increased anon residency and page cache thrashing. By bypassing readahead for zswap, the patch aims to reduce this overhead and improve performance. Measurements show significant gains in build time, zswap-in/out rates, and reduced swap readahead hits. The patch reuses existing code and adds a new helper function to check if a swap entry is synchronous.

This patch aims to improve the performance of memory cgroup (memcg) statistics flushing by reducing cacheline contention and prefetching issues. The author experimented with split rstat trees, but found that it introduced inconsistent and noisy numbers due to cacheline contention. Instead, they propose keeping the existing tree for userspace flushers and adding a 'slim' tree for in-kernel flushers, which would reduce overhead when updating hot stats. Ongoing Submitted 2026-10-10 🔥 TODAY [PATCH] sched/psi: Remove the RCU wait from trigger destruction Needs Work LLM (per-reviewer) Accepted

This patch removes the RCU (Read-Copy Update) wait from the destruction of PSI (Pressure Stall Information) triggers in the Linux kernel. The RCU wait was added to protect worker and trigger lookups, but it has become unnecessary due to changes in the PSI scheduling mechanism. The patch updates the psi_trigger_destroy function to use rcu_access_pointer instead of synchronize_rcu, allowing for more efficient destruction of triggers. This change is tested with various scenarios, including trigger churn, notifications, and cgroup removal, without introducing any warnings or issues.
