Needs Work LLM (per-reviewer) Under Review

This patch series addresses poor NUMA balancing behavior in a production deployment by modifying the VMA scan filters to no longer gate memory-tier promotion. The issue arises from the global balancing mode not being able to describe the intent of individual VMA/PTE walks, leading to unproductive socket-placement faults that prevent promotion. The patches introduce promotion-only NUMA protection walks and derive private VMA state in the folio eligibility check, allowing eligible shared folios to be promoted to a fast tier. Additionally, the patches separate VMA placement eligibility from partial-scan continuation and scan PID-inactive VMAs for promotion. The changes improve DRAM bandwidth, reduce CXL bandwidth saturation, and decrease request latency.

[PATCH pynfs v2] RPLY14: reconnect before retransmitting the call Neutral llm-chunked-no-replies Awaiting Review

This patch addresses an issue in the NFSv4 client where it fails to reconnect before retransmitting a request over the same socket, which is against the RFC7530 specification. The patch introduces a new method `reconnect_same_port` that drops the current connection and reconnects from the same local port, allowing the server to see a new transport with an unchanged (address, port) cache key. This change is necessary because the client should not retry a request unless the transport connection has been broken or the procedure being retried is the NULL procedure.

Ongoing Submitted 2026-09-21 🔥 TODAY [PATCH 1/2] mm: page_alloc: do not give all non-blocking requests reserve access Needs Work LLM (per-reviewer) Under Review

This patch addresses an issue where non-blocking allocation requests were given access to highatomic reserves unintentionally. The patch narrows the exemption for accessing these reserves to only contexts that have both ALLOC_NON_BLOCK and ALLOC_MIN_RESERVE flags set, which is specific to GFP_ATOMIC allocations. This change aims to prevent squandering of reserves on requests that don't need it, improving the overall performance of highatomic requests.

Ongoing Submitted 2026-09-21 Last comment 2026-09-22 ⏱ No recent activity [PATCH 2/2] mm: page_alloc: remove ALLOC_NON_BLOCK from ALLOC_RESERVES Needs Work LLM (per-reviewer) Under Review

This patch removes the ALLOC_NON_BLOCK flag from the ALLOC_RESERVES definition in the Linux kernel's page allocation code. The flag was previously used to grant access to a reserve of memory below the minimum watermark, but this caused issues when GFP_NOWAIT allocations were made under memory pressure. By removing the flag, the patch prevents direct reclaim and stalls during such bursts, ensuring that high-order atomic allocations are not disrupted by GFP_NOWAIT consumers. The patch also updates comments in the code to reflect the correct behavior of ALLOC_NON_BLOCK.
