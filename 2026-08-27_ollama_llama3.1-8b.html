This patch aims to improve performance by reducing unnecessary flushing of memory cgroup (memcg) statistics. It introduces a new approach that allows memcg stats to be flushed only when the number of updates exceeds a certain threshold, rather than at regular intervals. The patch also explores alternative approaches, such as scaling the flush threshold based on the memcg limit, but concludes that the new approach is more effective.

This patch series introduces Virtual Swap Space (VSwap), a new feature that allows for efficient and scalable swapping by decoupling swap entries from their backing storage. 🔥 TODAY [PATCH] mm/memcg: fix UAF in drain_all_stock() async work during offline Needs Work LLM (per-reviewer) Under Review

This patch fixes a use-after-free (UAF) bug in the Linux kernel's memory cgroup (memcg) implementation. The bug occurs when the `drain_all_stock()` function is called asynchronously during offline operations, and it can lead to a situation where the memcg is freed while the drain work is still pending. To fix this issue, the patch modifies the offline path to wait for the completion of the workqueue before freeing the memcg. This ensures that the memcg remains valid until all pending work has been completed.

Needs Work LLM (per-reviewer) Superseded

This patch series introduces PMD-level swap entries for anonymous THPs (Transparent Huge Pages) to allow them to survive the swap round-trip without needing khugepaged to collapse the range later. The PMD swap entry is a compact page-table encoding for HPAGE_PMD_NR consecutive swap slots, and does not promise that the swap cache always contains one PMD-sized folio. When the cache has split or per-slot state, users can either inspect individual slots directly or split the PMD swap entry and retry through the PTE path. The series is ordered so every consumer can handle PMD swap entries before the swap-out producer starts installing them.

This patch series optimizes the Zstandard (zstd) compression library in the Linux kernel by reducing unnecessary CPUID probes for BMI2 support. The current implementation probes for BMI2 support every time a compression or decompression context is set up, which can lead to performance issues due to serializing CPUID instructions on x86. This patch series introduces caching and dynamic dispatching of BMI2 support, resulting in significant performance improvements (up to 71% reduction in decompression time) by reducing the number of CPUID probes.
