[PATCH] mm/mempolicy: take a cpuset cookie for the interleave node count Neutral llm-chunked-no-replies Awaiting Review

This patch fixes a memory allocation bug in the Linux kernel's mempolicy module by taking a cpuset cookie around the count of nodes to be allocated from. The bug occurs when a concurrent cpuset rebind can cause a torn read of the nodemask, leading to an empty mask and incorrect allocation. The patch introduces a retry mechanism to ensure that the nodemask is valid before proceeding with the allocation. This fix has been measured to reduce zero counts by 87% in a 72-node VM.

🔥 TODAY Re: memcg stats flushing (WAS "Re: [PATCH] fuse: disable default bdi strictlimiting") Contentious LLM (per-reviewer) Under Review

This patch addresses the issue of high overhead in memcg stats flushing, particularly at high depths (8-16) where the extra latency can be up to 48ns. The problem arises from the use of rstat rate-limiting, which is arbitrary and bounded by time rather than actual stats updates. The proposed solution involves minimizing unnecessary overhead by not updating stats that don't require precision, and removing the rate-limiting mechanism. This approach aims to strike a balance between precision and performance, especially in scenarios where lock contention is a concern.
