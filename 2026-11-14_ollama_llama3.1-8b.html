Ongoing Submitted 2026-11-13 🔥 TODAY [PATCH] mm/mempolicy: ignore a bind policy whose nodes have no memory Needs Work LLM (per-reviewer) Under Review

This patch addresses a problem where a bind policy is treated as movable-only if its nodes have no memory, leading to allocation failures and VM fault leaks. The patch ignores such policies until the nodes regain memory, preventing these issues. This fix targets systems with CPUSETS=n and HOTREMOVE=y configurations.

This patch series introduces N_MEMORY_COMMON, a new concept for general-purpose memory separate from node memory (N_MEMORY). It creates a baseline to ensure private node memory is default opted-out of being touched by the MM, similar to ZONE_DEVICE. The series consists of three phases: introducing N_MEMORY_COMMON, defining memory not part of the general pool (N_MEMORY_PRIVATE), and adding feature bits for userland management.

Neutral llm-chunked-no-replies Awaiting Review

This patch series modifies how memory cgroup (memcg) statistics are read from the root cgroup, which is a critical component in Linux's memory management system. Currently, reading memcg stats for the root cgroup involves flushing all other cgroups' stats, which can be expensive and introduce latency. This patch proposes to instead use global counters that track memory usage across all cgroups, eliminating the need for these flushes. The changes are incremental, with some call sites already using global counters, while others will require additional patches to adapt. The goal is to reduce overhead and improve performance in scenarios where the root cgroup's stats are accessed frequently.

Ongoing Submitted 2026-11-04 🔥 TODAY [PATCH] mm/compaction: sample empty pageblocks again from a random offset Needs Work LLM (per-reviewer) Under Review

This patch modifies the Linux kernel's compaction algorithm to sample empty pageblocks from a random offset when the initial scan finds nothing. This is done to prevent aliasing issues that can cause free pages to be missed, particularly in sparse layouts or when memory is not aligned with the sampling grid. The change aims to improve the detection of free pages and reduce the likelihood of compaction failures, which can lead to stalled tasks and inefficient memory usage.

Ongoing Submitted 2026-11-13 🔥 TODAY [PATCH] Revert "sched/fair: Add SIS_UTIL support to select_idle_capacity()" Needs Work LLM (per-reviewer) Under Review

This patch reverts a previous change that added SIS_UTIL support to the select_idle_capacity() function in the Linux kernel's scheduler. The reverted change caused issues when the scan budget was zero, leading to incorrect idle CPU selection and increased latency for certain workloads. The patch restores the original behavior of searching the allowed domain for an idle CPU, which can increase scan CPU cost but ensures accurate idle CPU selection. This change is intended to fix a performance regression introduced by the previous commit.

This patch series optimizes the x86 memcpy() function for ERMS CPUs without FSRM by using REP MOVSB for large copies (2048 bytes and larger). The approach taken is to split the changes into two patches: one that prepares the scalar register allocation, and another that adds the ERMS size check and adopts Linus's FSRM entry layout. This allows REP MOVSB to replace the existing jump to memcpy_orig(), keeping RET in ordinary text. The patch also addresses issues related to return handling and register reloads.
