🔥 TODAY [PATCH 1/5] x86/paravirt: Use static_call() for the paravirt spinlock ops Neutral LLM (per-reviewer) Under Review

This patch replaces the use of paravirt-ops ALTERNATIVE machinery for dispatching spinlock operations on x86 architecture with static_call(). This change allows the target function to be updated at runtime, which is necessary for implementing a contended_release tracepoint. The patch updates several files in the kernel and includes changes to support module safety and boot testing on native and KVM PV guest systems.

[PATCH 2/5] locking: Factor out queued_spin_release() Positive llm-chunked-no-replies Awaiting Review

This patch introduces a new function, queued_spin_release(), which is an arch-overridable release primitive for spinlocks. It creates a generic wrapper around the existing queued_spin_unlock() function, allowing architectures to customize only the release behavior if needed. The MIPS architecture's override is renamed to match this change, but x86 paravirt remains unchanged as it directly overrides queued_spin_unlock(). This patch does not introduce any functional changes and is intended to facilitate future tracing and debugging efforts.

[PATCH 3/5] locking/qspinlock: Add contended_release tracepoint Positive llm-chunked-no-replies Awaiting Review

This patch adds a contended_release tracepoint to the qspinlock locking mechanism, allowing for attribution of contended spinlocks to their holders. The patch combines contention check, trace call, and release into an out-of-line function to minimize overhead. It also introduces a new configuration option to enable or disable this feature. The patch aims to provide more detailed information about lock contention in the Linux kernel.

[PATCH 4/5] tracing/lock: Use TRACE_EVENT_FN() for contended_release Neutral llm-chunked-no-replies Awaiting Review

This patch modifies the tracing of lock contention events in Linux by using a new macro, TRACE_EVENT_FN(), for the contended_release event. This change allows for more flexibility and customization when tracing this specific event. The patch introduces weak no-op hooks for architectures to override if they need custom behavior. Currently, these hooks are empty, resulting in no functional changes until an architecture overrides them.

[PATCH 5/5] x86/paravirt: Trace contended_release on unlock Neutral llm-chunked-no-replies Awaiting Review

This patch optimizes the unlock path for PARAVIRT_SPINLOCKS=y kernels by swapping the target of a static_call() to a traced unlock when the contended_release tracepoint is enabled. This reduces overhead when tracing is disabled, as it avoids a branch that would otherwise be taken even if tracing is off. The patch also introduces two new traced unlock variants and updates the pv_is_native_spin_unlock function accordingly.
