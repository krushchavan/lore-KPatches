This patch updates the Btrfs scrub's throttling mechanism to handle bandwidth limits below 512KiB/s. The existing implementation had a practical minimum limit of 512KiB/s due to its interval-based approach, but this update introduces a burst duration concept that allows for more flexible and efficient throttling at lower limits. [PATCH 4/4] btrfs: scrub: size read bios to the bwlimit 10ms burst Positive llm-chunked-no-replies Accepted

This patch adjusts the size of read bios in Btrfs scrub to be more burst-aware, taking into account the specified bandwidth limit and its duration. The goal is to avoid submitting large bios that would lead to long sleeps, which can cause pacing issues at lower bandwidth limits. Instead, the code computes a burst size based on the bandwidth limit and duration, and uses this value to determine the bio size. This approach allows for more natural pacing of I/O operations, especially at higher bandwidth limits. The patch also introduces a throttle variable to skip throttling parity reads during scrubs.

  • [3/3] mm/page_alloc: disable IRQs around the remaining pcp drains
Neutral llm-chunked-no-replies Awaiting Review

This patch series addresses a performance issue in the Linux kernel's page allocation mechanism by modifying the handling of interrupts and locks. The problem arises when IRQs are disabled to prevent deadlocks, allowing interrupt handlers to fire before tasks can release their locks. This leads to increased contention on the zone lock, causing softlockups. To resolve this, the patch series reorders the locking sequence so that IRQs remain disabled until after the pcp lock is released, giving interrupt handlers a better chance of acquiring the pcp lock and reducing contention on the zone lock.

🔥 TODAY Re: [PATCH bpf-next v3 0/4] bpf: Check recursion per task for preemptible programs Needs Work LLM (per-reviewer) Under Review

This patch proposes a new approach to concurrency-safe private stacks in Linux, which are currently used by BPF programs. The existing per-prog per-cpu model is not sufficient for concurrent tasks on the same CPU, leading to potential corruption and overflow/underflow issues. The proposed solution introduces a per-prog per-cpu pool of private stacks, where each program acquires an available slot at invocation time and releases it on exit. This allows multiple tasks to use separate private stacks concurrently, eliminating the need for marking private stacks and enabling the use of a new per-task per-prog recursion guard. The patch is a proof-of-concept implementation for x86_64 trampolines and has been validated with bpftrace programs.

Ongoing Submitted 2026-11-19 🔥 TODAY [PATCH] drm/i915/gem: Skip writeback of shmem folios with extra references Needs Work LLM (per-reviewer) Under Review

This patch modifies the drm/i915/gem module to skip writeback of shmem folios that have extra references, preventing a race condition where a stale TLB entry can still store data to an unmapped folio until the TLB is flushed. The change ensures that such folios are left to reclaim as mapped ones would be, rather than being written back from swap without the stored data.

This patch series addresses a performance issue caused by the high-order watermark check not honouring the ALLOC_NOFRAGMENT flag in memory pressure situations. The check currently counts free pages of every migratetype, leading to incorrect results and stalls in compaction. The patches modify the watermark checks to take into account the request's migratetype and skip free lists that cannot be used. This is achieved by passing the alloc_flags to try_to_free_pages() and modifying the should_reclaim_retry() function. The changes are based on a benchmark that shows significant improvements in performance, with 64K mTHP faults under memory pressure stalling 18 times less often than without the patch series.
