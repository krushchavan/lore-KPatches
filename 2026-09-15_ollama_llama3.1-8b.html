  • [2/3] mm: swap: refault on swap-in, not in the swap cache allocator Submitted 2026-09-11
  • [3/3] mm: zswap: preserve the workingset shadow across writeback Submitted 2026-09-11
Needs Work LLM (per-reviewer) Under Review

This patch series fixes a problem in the zswap writeback path where workingset refaults were being over-counted and eviction cookies were being lost, leading to inaccurate workingset detection. The patches preserve the shadow within zswap itself by parking the captured shadow in the zswap tree instead of erasing it when writing back to disk. This is done without introducing new swap-table or swap-slot state. As a result, refault evaluation is moved out of the swap-cache allocator and into the swap-in callers, preventing miscounted refaults. The patches were tested with a sysbench OLTP workload and showed significant reductions in workingset refaults, activations, and restores (-48%, -59%, and -53% respectively), while maintaining comparable writeback volume and unaffected throughput.

[PATCH v3 0/3] reduce reflink src inode lock contention Neutral llm-chunked-no-replies Awaiting Review

This patch reduces contention on the src inode lock during reflink operations by attempting to perform some writeback outside of the lock and downgrading the lock to shared when safe. The approach involves pre-flushing the source file before taking the locks, skipping flush if there are writers, and then downgrading the lock for tree walking. This should reduce contention on the src inode i_rwsem during reflink operations.

[PATCH v3 1/3] btrfs: pre-flush reflink source before taking inode locks Neutral llm-chunked-no-replies Awaiting Review

This patch optimizes the reflink operation in Btrfs by pre-flushing the source file before taking inode locks, reducing contention between writers and readers. The current logic blocks concurrent usage of inode locks during writeback, leading to performance issues. This patch introduces an optimistic btrfs_wait_ordered_range() call without locks, relying on subsequent calls under locks for correctness. In case of concurrent writes while unlocked, the worst-case scenario is a redundant writeback, considered a reasonable trade-off for avoiding reader lock contention in common cases.

[PATCH v3 2/3] btrfs: skip unlocked reflink source flush if the inode has writers Neutral llm-chunked-no-replies Awaiting Review

This patch modifies the Btrfs reflink source flush behavior to skip the unlocked flushing if there are active writers dirtying pages. This is done by checking for outstanding writable file descriptors or memory mappings, which can cause redundant writeback. The change aims to reduce write amplification and user-space stalls in certain workloads, particularly those with long open file descriptors or continuous writes.

[PATCH v3 3/3] btrfs: downgrade the reflink source inode lock for tree walking Neutral llm-chunked-no-replies Awaiting Review

This patch downgrades the lock on the source inode during reflink operations from exclusive to shared, allowing other processes to access the file while a reflink is in progress. This improves performance by reducing stalls caused by concurrent clones and lseeks or dio reads on the src file. The patch also adds checks for direct IO writes that come in under EOF and ensures that the inode flag 'BTRFS_INODE_REFLINK_SRC' is visible to the dio writer. Additionally, it remains exclusive to dio reads through finishing the prep to prevent starving the clone on a stream of dio readers.

Ongoing Submitted 2026-09-12 🔥 TODAY [PATCH] mm/madvise: reclaim isolated folios if PTE restart fails Contentious LLM (per-reviewer) Under Review

This patch addresses a concurrency issue in the Linux kernel's madvise functionality. When MADV_PAGEOUT is used to collect isolated folios, a concurrent operation can remove or replace the PTE table while the lock is dropped, causing pte_offset_map_lock() to return NULL and bypassing reclaim_pages(). The patch routes this failure through the existing cleanup path, ensuring that any collected folios are reclaimed or put back. This fix prevents a situation where isolated folios remain off the LRU with elevated references.

Ongoing Submitted 2026-09-12 🔥 TODAY [PATCH] proc/task_mmu: handle special PMDs in clear_refs and pagemap Needs Work LLM (per-reviewer) Under Review

This patch fixes a bug in the Linux kernel's /proc/PID/pagemap and /proc/PID/clear_refs functionality. The issue arises when a special PMD (Page Map Directory) is installed from a PFN (Physical Frame Number) that does not have a corresponding memmap entry. This causes the kernel to oops when trying to read or write these mappings. To fix this, the patch uses vm_normal_folio_pmd and vm_normal_page_pmd functions instead of pmd_folio and page_folio in certain paths, allowing the kernel to handle special PMDs correctly. The patch has been tested on QEMU with a test driver and has been reported to resolve the issue.

[PATCH] fuse: don't drop destination page cache on a zero byte copy reply Neutral llm-chunked-no-replies Awaiting Review

This patch fixes a bug in the FUSE (Filesystem in Userspace) kernel module where it incorrectly drops the destination page cache when the server replies that no bytes were copied during a copy_file_range operation. The issue occurs when the source file is shorter than the size cached by the kernel, causing the end of the range to be -1 and resulting in all folios being dropped from the destination mapping. The patch adds a check for zero byte copies and only clears the cache if bytes were actually copied.
