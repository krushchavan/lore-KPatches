Ongoing Submitted 2026-09-16 🔥 TODAY [PATCH] btrfs: keep unused block groups queued when a pass fails Needs Work LLM (per-reviewer) Under Review

This patch addresses a potential issue in the btrfs file system where unused block groups can be leaked and lead to spurious ENOSPC errors. The problem occurs when an error is encountered while deleting unused block groups, causing them to be skipped and not re-queued for later processing. To fix this, the patch changes the logic of the deletion loop to break out of it when an error is encountered, rather than skipping the rest of the block groups. Additionally, it links the failing block group to a retry list at the individual failure sites, ensuring that it is not leaked.

This patch reduces contention on the src inode lock during reflink operations by attempting to write back the source file outside of the lock and downgrading the lock to shared when safe. The approach involves pre-flushing the source file, skipping flush if there are writers, and then downgrading the lock for tree walking. This should improve performance in scenarios with high contention on these locks.

Ongoing Submitted 2026-09-15 🔥 TODAY [PATCH v3 1/3] btrfs: pre-flush reflink source before taking inode locks v2 → v3 Neutral LLM (per-reviewer) Under Review

This patch optimizes the reflink operation in Btrfs by pre-flushing the source file before taking inode locks, reducing contention between writers and readers. The current logic blocks concurrent usage of inode locks during writeback, leading to performance issues. This patch introduces an optimistic btrfs_wait_ordered_range() call outside the locked region, ensuring correctness while minimizing the risk of double-writeback in case of concurrent writes. The change improves the performance of reflink operations by allowing direct reads and seeks to proceed concurrently with writeback.

Ongoing Submitted 2026-09-15 🔥 TODAY [PATCH v3 3/3] btrfs: downgrade the reflink source inode lock for tree walking v2 → v3 Neutral LLM (per-reviewer) Under Review

This patch improves the performance of reflink operations in Btrfs by downgrading the lock on the source inode from exclusive to shared during tree walking. This is done to avoid blocking other shared lock users, such as direct I/O writers and readers, which can cause stalls. The patch also adds a new flag to indicate when an inode is being used as a reflink source, and ensures that this flag is visible to direct I/O writers. Additionally, it remains exclusive for dio reads until the inode_dio_wait() function is finished with its work.

This patch series addresses a performance issue in NUMA balancing by separating promotion-only scans from socket-placement scans. The current implementation prevents hot memory in read-only file mappings and VMAs without recent PID activity from being promoted to a faster tier, leading to increased request latencies. The patches introduce a new protection flag (MM_CP_PROT_NUMA_PROMO_ONLY) that allows for promotion-only scans, enabling eligible shared folios to be promoted and reducing the impact of filters on memory-tier promotion. This change improves performance by allowing hot memory to be moved to faster tiers, resulting in increased bandwidth usage and reduced request latencies.

This patch adds a test case to the fstests suite that exercises the btrfs filesystem's handling of ENOMEM errors in synchronous directory operations. The test uses fault injection knobs to simulate an -ENOMEM error when creating a directory, and verifies that the operation returns ENOMEM to userspace without aborting the filesystem. The test also checks that subsequent operations, including a mount cycle with orphan cleanup and automatic fsck, complete successfully. Additionally, this patch introduces generic helpers for driving the kernel's fail_function interface in the common/inject file.
