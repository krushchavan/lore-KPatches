Needs Work LLM (per-reviewer) RFC

This patch aims to reduce the number of I/O requests on a swap device by keeping reclaim batches contiguous. The current implementation of swap allocation and deallocation can lead to scattered writes, resulting in increased I/O requests. The patch modifies the allocator to allocate contiguous free slots for a reclaim batch, reducing the number of small requests and improving throughput. This is achieved by informing the allocator about the size of the batch and allowing it to allocate contiguous slots accordingly. The goal is to reduce the overhead of swap I/O operations and improve system performance.

Ongoing Submitted 2026-10-30 🔥 TODAY [PATCH v2] mm/mempolicy: recompute automatic interleave weights on memory hotplug v1 → v2 Needs Work LLM (per-reviewer) Under Review

This patch addresses a performance regression caused by outdated automatic interleave weights in the Linux kernel's memory policy module (mm/mempolicy). When nodes gain or lose memory, their weights are not recalculated from their reported bandwidths, leading to an uneven distribution of data and potential overload. The patch introduces a new function, wi_state_refresh(), which recomputes the weights based on the recorded bandwidth whenever a node gains or loses its first/last memory. If allocating new weights fails, it warns once and continues with the next recompute starting from the full bandwidth table.

Needs Work LLM (per-reviewer) Under Review

This patch series addresses six races in the Linux kernel's memory management code that can cause crashes or incorrect behavior when memory is offline. The patches introduce a new function, pfn_walk, which waits for pending page walkers before poisoning the memory map, and modify various functions to use this new function or hold get_online_mems() instead. This ensures that memory is not accessed after it has been marked as offline, preventing crashes and incorrect behavior. The changes are tested on a QEMU guest with three NUMA nodes and a pc-dimm left offline at boot, and the results show that the patches fix all six races without introducing any significant performance cost.

Needs Work LLM (per-reviewer) Under Review

This patch series addresses the issue of memcg stats flushing, which can be costly and introduce staleness in statistics. For the root memcg, it's possible to directly read global counters instead of going through rstat, as they are always up-to-date. The patches modify various call sites to use node counters for reading LRU sizes, working set, rotation, and reclaim writeback counts. This approach reduces the number of flushes required, especially for the root memcg, which can be a performance bottleneck. The changes also improve the accuracy of statistics by reducing staleness. The series consists of three patches: one fixes the zswap shrinker's count for the root memcg, another adds a function to read node counters for the root memcg, and the third modifies DAMON's quota goals to use node counters instead of flushing.
