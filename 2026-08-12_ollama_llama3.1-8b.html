This patch allows the nfs4_handle_delegation_recall_error() function to silently handle the -ERESTARTSYS error code, preventing it from emitting a printk() message when a process is interrupted by a signal while waiting on a delegrecall. This change addresses an issue where the kernel would print a potentially confusing error message in such situations. This patch set hardens the netlink listener interfaces in the NFS daemon (nfsd) and SunRPC code by addressing several issues that were causing stalls and hangs. The changes include rejecting invalid transport names, capping the number of listener_set requests at 1024 entries, improving error handling for registration failures, and bounding the local rpcbind client to a single attempt. While this patch set improves performance and reduces stalls, it does not address the root cause of the issues, which is the synchronous nature of rpcbind calls. A separate patchset is planned to make these calls asynchronous.

Last comment 2026-08-13 Re: [PATCH] btrfs: properly cleanup replace_task when the replace failed to start Needs Work LLM (per-reviewer) Under Review

This patch fixes a bug in the Btrfs file system where the replace_task pointer is not properly cleaned up when a device replacement fails to start. The issue occurs because the dev_replace->replace_task pointer is left pointing to the task that started the replace, even if it failed. This can cause problems later on, such as stale pointers and potential rwsem releases. The patch fixes this by resetting the dev_replace->replace_task pointer in all error paths of btrfs_dev_replace_finishing().

Ongoing Submitted 2026-08-06 Last comment 2026-08-18 memcg stats flushing (WAS "Re: [PATCH] fuse: disable default bdi strictlimiting") Needs Work LLM (per-reviewer) Changes Requested

This patch addresses the issue of stale memory cgroup (memcg) stats causing premature OOM kills by proposing a solution to reduce the overhead of updating and flushing these statistics. The idea is for memcg to accumulate updates on a per-CPU basis, then propagate them up to a global atomic counter when it reaches a certain threshold, eliminating the need for frequent flushing. This approach aims to scale better for large machines with many cores and focuses on reducing the number of stats that require flushing, specifically NR_FILE_DIRTY and NR_WRITEBACK in the writeback case.

Last comment 2026-08-18 Re: memcg stats flushing (WAS "Re: [PATCH] fuse: disable default bdi strictlimiting") Needs Work LLM (per-reviewer) Under Review

This patch addresses the issue of memcg stats staleness, which can lead to inaccurate working set size calculations and potentially cause false or missed activations of refaulted pages. The patch focuses on the vmscan category, where accurate stats are crucial for determining whether reclaim can deactivate. It introduces a new approach that reduces the frequency of flushing stats, minimizing the impact on other categories like zswap, cachestat(), and working set. This change aims to strike a balance between accuracy and performance, ensuring that the kernel can still make informed decisions despite some staleness in stats.

Last comment 2026-08-13 Re: [PATCH 0/4] mm/mempolicy: introduce package-aware weighted interleave Needs Work LLM (per-reviewer) New Version Expected

This patch series introduces package-aware weighted interleave, which modifies the existing weighted interleave mechanism to respect the initiator's point of view when making memory allocations. The goal is to simplify user configuration and improve performance by reducing cross-socket memory movements. The approach involves adding a restriction to the existing weights, rather than introducing new per-socket or per-node weights as initially misunderstood. This change aims to promote socket-local memory allocation and demote cross-socket allocations, potentially eliminating the need for explicit NUMAB2 promotions. The patch series consists of four patches, with one being particularly large (1k lines) and suggested to be split into smaller patches for easier review.

Contentious LLM (per-reviewer) RFC

This patch series improves the performance of follow_page_mask() by allowing it to batch lookups and reduce lock contention. The current implementation walks the page tables one page at a time, even when contiguous pages are requested. This series changes follow_page_mask() to return a count and an array of pages, instead of a single struct page, enabling more efficient handling of large folios. Patches 1-4 prepare for this change by refactoring and splitting existing functions. Patch 5 optimizes huge page paths, patch 6 simplifies the handling of subpages, and patches 7 and 8 implement batched lookups and refcount batching, respectively. The series includes benchmark results showing a significant performance improvement.

Needs Work LLM (per-reviewer) Under Review

This patch set optimizes the blk_cgroup_congested() function by skipping unnecessary walks of the block cgroup (blkcg) hierarchy when no tasks are being throttled. The current implementation incurs a significant performance cost due to frequent cache line loads and RCU read-side pairs, especially in systems with deep container hierarchies. To address this, the patch introduces a global gate that only performs the walk when there is at least one blkcg with a non-zero congestion count. Additionally, two patches fix issues that can leave a blkcg permanently marked congested, which would otherwise cause unnecessary throttling of tasks in affected cgroups.
