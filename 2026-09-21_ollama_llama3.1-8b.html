[PATCH v6 0/3] mm: zswap: free cold writeback folios promptly 3 patches
Show 3 individual patches
  • [1/3] mm: swap: move LRU insertion out of the swap cache allocator
  • [2/3] mm: swap: drop dropbehind swap cache folios on writeback completion
  • [3/3] mm: zswap: drop cold writeback folios via swap dropbehind
Neutral LLM (per-reviewer) Under Review

This patch set extends the existing dropbehind mechanism to swap cache folios, allowing zswap to opt into it and free cold writeback folios promptly. Currently, when zswap writes an entry back, it allocates a folio and leaves it on the LRU for page reclaim to find and free later, wasting a reclaim scan and keeping cold memory resident longer than necessary. The patch set moves LRU insertion out of the swap cache allocator, drops dropbehind swap cache folios on writeback completion, and has zswap allocate its writeback folio off the LRU and mark it dropbehind to take advantage of this mechanism.

This patch refactors the zonelist constructors and iterators in the Linux kernel to make them more flexible and modular. The existing behavior of picking nodes from N_MEMORY is made explicit, allowing callers to narrow the set of nodes used for fallback lists. A new function find_next_best_node_in() takes a candidate set as an argument, making it easier to build zonelists over specific sets of nodes. Additionally, the per-node construction loop in build_zonelists() is extracted into a separate function build_node_zonelist(), which can be parameterized on the candidate nodemask and destination zonelist index. These changes enable more flexible and efficient management of zonelists, particularly for generating private node zonelists.

[PATCH 2/2] mm: page_alloc: remove ALLOC_NON_BLOCK from ALLOC_RESERVES Neutral llm-chunked-no-replies Awaiting Review

This patch removes the ALLOC_NON_BLOCK flag from the ALLOC_RESERVES definition in the Linux kernel's page allocation system. The flag was previously used to grant access to a reserve of memory below the minimum watermark, but this caused issues when GFP_NOWAIT allocations were made under memory pressure. By removing the flag, the patch ensures that GFP_NOWAIT allocations are stopped short at the minimum watermark, preventing direct reclaim and stalls. This fix addresses a problem where high-order atomic allocations were being denied due to GFP_NOWAIT consumers accessing reserved memory they weren't entitled to.
