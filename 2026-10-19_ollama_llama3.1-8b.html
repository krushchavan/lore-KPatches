🔥 TODAY [PATCH v2] cgroup/cpuset: use mems_allowed_seq when checking a policy nodemask Positive LLM Accepted

This patch addresses a potential performance issue in the cgroup/cpuset subsystem by introducing a retry mechanism when checking a policy nodemask against the current task's mems_allowed. The problem arises from the fact that cpuset updates rebind the task's mempolicy and change mems_allowed in separate steps, which can cause a spurious numa placement miss under certain conditions. The patch uses the mems_allowed_seq to retry the intersection until it is stable.

🔥 TODAY [PATCH] mm/page_alloc: let the highest memory node recover from hopeless state Needs Work LLM (per-reviewer) Under Review

This patch fixes a problem where the highest memory node in a system cannot recover from a 'hopeless' state, even when its zone recovers above the high watermark. The issue arises because the current code checks if there is another memory node available for allocations to fall back to by looking at the next higher-numbered node ID, which always returns false for the highest node. This patch changes the check to count the number of nodes with a state of N_MEMORY, effectively checking if any other node exists. As a result, the highest node can now recover from its hopeless state and kswapd will be re-enabled.

Last comment 2026-10-20 [PATCH v3] mm: unqueue deferred split folios outside the lruvec lock v1 → v2 → v3 Positive LLM (per-reviewer) Under Review

This patch modifies the Linux kernel to unqueue deferred split folios outside of the lruvec lock, which is currently held in various paths such as move_folios_to_lru() and folio_batch_move_lru(). The lruvec lock protects the folio's LRU list and reclaim lists, but the deferred split queue lives on a separate list_lru with its own per-memcg per-node lock. By unqueuing the folios outside of the lruvec lock, the patch reduces contention on this critical section, which is highly contended and runs with IRQs disabled. This change was motivated by performance issues observed in a fault microbenchmark, where queueing small mTHP folios on the deferred split queue caused significant lock contention.

Ongoing Submitted 2026-10-09 🔥 TODAY [PATCH v3] mm: page_alloc: make defrag_mode retries follow the promoted order v2 → v3 Needs Work LLM (per-reviewer) Under Review

This patch modifies the page allocation mechanism in Linux to make defragmentation mode retries follow the promoted order of requests, rather than the original request order. This change aims to prevent indefinite retrying by order-0 requests and reduce memory pressure caused by frequent direct reclaim runs. The promoted order is computed once per iteration and passed to relevant functions, ensuring consistency across different callers. Additionally, the patch resets retry counters when a promoted request takes the fallback path, allowing for a full retry budget before OOM killing is considered.

Needs Work LLM (per-reviewer) RFC

This patch series introduces a new mechanism to read from the page cache without taking a reference on folios, which can lead to refcount bouncing between CPUs. The approach involves marking accessed folios as PG_rcu_free and deferring their free until an RCU grace period. This allows for more efficient handling of small reads and reduces the overhead of lock contention. The series includes 18 patches that implement this new mechanism in various parts of the Linux kernel, including filemap_read(), shmem, and memory_failure(). The goal is to improve performance on systems with many CPUs by reducing the number of references taken on folios and minimizing the impact of refcount bouncing.
