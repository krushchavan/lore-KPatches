Ongoing Submitted 2026-08-04 🔥 TODAY [PATCH 3/5] locking/qspinlock: Add contended_release tracepoint Needs Work LLM (per-reviewer) Accepted

This patch adds a new tracepoint called contended_release to the qspinlock locking mechanism. The purpose of this tracepoint is to capture information about the holder of a contended spinlock, which is not possible with mutex and rw_semaphore due to their lack of an owner field. The patch combines the contention check, trace call, and release into a single out-of-line function to minimize performance overhead. The patch also introduces a new configuration option to enable or disable this feature, and it includes measurements showing that the binary size impact is minimal even when the tracepoint is enabled.

Ongoing Submitted 2026-08-04 ⏱ No comments yet [PATCH 4/5] tracing/lock: Use TRACE_EVENT_FN() for contended_release Neutral LLM Accepted

This patch series converts the contended_release trace event to use TRACE_EVENT_FN(), which allows for more flexible and efficient tracing of lock contention. The change involves replacing the static branch that gates the contended_release call with a callback-based approach, using weak no-op hooks for architectures that don't override them.

Ongoing Submitted 2026-08-04 🔥 TODAY [PATCH 5/5] x86/paravirt: Trace contended_release on unlock Needs Work LLM (per-reviewer) Accepted

This patch optimizes the unlock path for PARAVIRT_SPINLOCKS=y kernels by swapping the target of a static call to a traced unlock function when the contended_release tracepoint is enabled. This reduces overhead when tracing is disabled, as it avoids a branch that would otherwise be taken even if tracing is off. The patch also introduces two new traced unlock functions and updates the pv_is_native_spin_unlock() function accordingly.
