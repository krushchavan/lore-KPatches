Ongoing Submitted 2026-10-20 🔥 TODAY [PATCH v1] memcg: fix cacheline contention between lruvec stat updates and LRU lists Needs Work LLM (per-reviewer) Under Review

This patch addresses cacheline contention between lruvec stat updates and LRU lists by modifying the update paths to avoid accessing struct mem_cgroup_per_node directly. Instead, it uses the memcg to access the per-cpu lruvec stats, reducing unnecessary cache line fetches and contention on the lru_lock critical section. The patch was motivated by analysis of perf c2c output showing high contention on the first 64 bytes of mem_cgroup_per_node, even though there were no writes to it. The fix is expected to improve performance in multi-threaded workloads with many threads faulting in pages in a single memcg.

Ongoing Submitted 2026-10-19 🔥 TODAY [PATCH v3] mm: unqueue deferred split folios outside the lruvec lock v1 → v2 → v3 Needs Work LLM (per-reviewer) Under Review

This patch modifies the Linux kernel to unqueue deferred split folios outside of the lruvec lock, which is currently held in various paths such as move_folios_to_lru() and folio_batch_move_lru(). The lruvec lock protects the folio's LRU list and reclaim lists, but the deferred split queue lives on a separate list_lru with its own per-memcg per-node lock. By unqueuing the folios outside of the lruvec lock, the patch reduces contention on this critical section, which is highly contended and runs with IRQs disabled. This change was motivated by performance issues observed in a fault microbenchmark, where queueing small mTHP folios on the deferred split queue caused significant lock contention.

This patch addresses a race condition on PREEMPT_RT by publishing the NULL pointer before dropping the css reference in the memcontrol code. Ongoing Submitted 2026-10-09 🔥 TODAY [PATCH v3] mm: page_alloc: make defrag_mode retries follow the promoted order Needs Work LLM (per-reviewer) Under Review

This patch modifies the page allocation mechanism in Linux to make defragmentation mode retries follow the promoted order of requests, rather than the original request order. This change aims to prevent indefinite retrying by order-0 requests and reduce memory pressure caused by frequent direct reclaim runs. The promoted order is computed once per iteration and passed to relevant functions, ensuring consistency across different callers. Additionally, the patch resets retry counters when a promoted request takes the fallback path, allowing for a full retry budget before OOM killing is considered.

This patch replaces vswap's cluster_info storage from an xarray of individually allocated clusters to a VM_SPARSE vmalloc array, simplifying access and reducing memory allocation overhead. The change eliminates the need for per-cluster RCU grace periods and reduces the size of swap clusters. It also removes the wrapper function swap_cluster_info_dynamic and merges the two cluster arrays into si->cluster_info. As a result, swap clusters are no longer destroyed when they empty, but instead wait to be reused like physical devices' clusters.

Last comment 2026-10-22 [PATCH] mm/page_counter: use WRITE_ONCE() for emin/elow when parent is the root Needs Work LLM (per-reviewer) Under Review

This patch fixes a data-race issue in the Linux kernel's page_counter module by using WRITE_ONCE() for storing emin and elow values when the parent is the root. The problem occurs because multiple reclaimers can update these values simultaneously without locks, leading to potential tearing of memory. The fix uses WRITE_ONCE() to ensure that these stores are atomic, even with CONFIG_KCSAN_STRICT=y enabled. This change has no functional impact as readers already accept stale values and compilers emit a single word-sized store either way.
