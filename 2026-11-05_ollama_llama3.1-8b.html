The patch series addresses a performance regression in Linux kernel version 7.3, which increased swap I/O requests by up to 59% on certain devices. The issue arises from the interaction between two commits: one that prefers non-full clusters over free ones and another that frees swap slots on exclusive write faults. Ongoing Submitted 2026-10-30 🔥 TODAY [PATCH v2] mm/mempolicy: recompute automatic interleave weights on memory hotplug v1 → v2 Needs Work LLM (per-reviewer) Under Review

This patch addresses a performance regression caused by outdated automatic interleave weights in the Linux kernel's memory policy module (mm/mempolicy). When nodes gain or lose memory, their weights are not recalculated from their reported bandwidths, leading to an uneven distribution of data and potential overload. The patch introduces a new function, wi_state_refresh(), which recomputes the weights based on the recorded bandwidth whenever a node gains or loses its first/last memory. If allocating new weights fails, it warns once and continues with the next recompute starting from the full bandwidth table.

Ongoing Submitted 2026-10-27 🔥 TODAY [PATCH RFC fstests] generic: add a test for multigrain timestamps Needs Work LLM (per-reviewer) Under Review

This patch adds a test to ensure that multigrain timestamps are working correctly in Linux kernels. The test, called 'mgtime', checks that the mtime and ctime of a file appear to change even when there are multiple writes in quick succession. This is particularly important for filesystems like ext4, f2fs, btrfs, tmpfs, and xfs, which support multigrain timestamps but may not be universally supported on all filesystems. The test uses a loop to write to a file 1000 times and then checks that the mtime and ctime are different from the previous value each time. If the values do not change, the test fails.

Ongoing Submitted 2026-10-29 🔥 TODAY [PATCH v2] mm: move LRU size stat updates out of lru_lock in folio batches v1 → v2 Needs Work LLM (per-reviewer) Under Review

This patch moves the updates of LRU size statistics out of the lru_lock critical section in folio batches, which reduces contention and improves throughput. The stats are accumulated while holding the lock and applied after dropping it, reducing the overhead of cache misses and improving performance. This change is particularly beneficial for workloads with many threads faulting and freeing memory in a single memcg, where the hold time of lru_lock directly limits throughput. The patch also moves cost_lock into the hole after lru_lock to make room for the batch pointer, keeping struct lruvec from growing. The stats may lag behind the LRU lists by one batch, but this is within the per-cpu batching already present.

This patch series addresses the issue of memcg stats flushing, which can be costly and introduce staleness in statistics. For the root memcg, it's possible to directly read global counters instead of going through rstat, as they are always up-to-date. The patches modify various call sites to use node counters for reading LRU sizes, working set, rotation, and reclaim writeback counts. This approach reduces the number of flushes required, especially for the root memcg, which can be a performance bottleneck. The changes also improve the accuracy of statistics by reducing staleness. The series consists of three patches: one fixes the zswap shrinker's count for the root memcg, another adds a function to read node counters for the root memcg, and the third modifies DAMON's quota goals to use node counters instead of flushing.

This patch series moves the stock implementation from memcontrol to page_counter, allowing for better separation of charge caching and policy management. The stock is a per-CPU cache of precharged pages that speeds up small allocations by avoiding frequent walks of the page_counter hierarchy. By moving it to page_counter, the patch simplifies the handling of stock in non-leaf cgroups and prepares for future improvements. It also ensures that locking behavior remains unchanged and that exact charging is preserved for non-spinning callers.
