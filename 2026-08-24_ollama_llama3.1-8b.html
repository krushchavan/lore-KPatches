Needs Work LLM (per-reviewer) Accepted

This patch series improves memory management for zswap by implementing a mechanism to promptly free cold writeback folios, reducing unnecessary reclaim scans and keeping cold memory resident for longer than necessary. The existing dropbehind mechanism is extended to swap cache folios, allowing zswap to opt into it. The patches move LRU insertion out of the swap cache allocator, drop dropbehind swap cache folios on writeback completion, and modify zswap to allocate its writeback folio off the LRU and mark it as dropbehind.

🔥 TODAY [PATCH] mm/mempolicy: refcount the weighted interleave state instead of copying it Needs Work LLM (per-reviewer) New Version Expected

This patch refactors the handling of the weighted interleave state in the Linux kernel's memory policy module. Instead of copying the state on every access, it introduces a reference counting mechanism to manage the state's lifetime. This change reduces memory allocation and deallocation overhead, fixes a bug related to GFP_KERNEL and partial allocations, and ensures that the state is properly cleaned up even in the presence of concurrent accesses.

Contentious LLM (per-reviewer) Accepted

This patchset replaces khugepaged's anonymous collapse mechanism with a new engine that can collapse sub-PMD ranges, built around migration entries and frozen folios to improve scalability and reduce disruption to the workload being collapsed. The old mechanism held the address space still by locking it, while the new engine makes the sources themselves inert between two barriers, allowing the copy to run without holding any lock. This change aims to fix limitations in the original implementation, particularly with PMD-granular operations and VMA alignment.

Ongoing Submitted 2026-08-19 🔥 TODAY [PATCH] mm/huge_memory: transfer the pmd dirty bit to the folio on zap Needs Work LLM (per-reviewer) Under Review

This patch addresses an issue where the pmd dirty bit is not being transferred to the folio when a huge page is zapped, leading to potential silent data loss in certain file systems like xfs. The problem arises because the TLB flush is deferred and can occur after the rmap has been dropped under the pmd lock, causing stale TLB entries to remain. To fix this, the patch aims to transfer the pmd dirty bit to the folio on zap, ensuring that data integrity is maintained even in the presence of concurrent writes.
