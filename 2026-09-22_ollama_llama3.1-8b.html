[PATCH 1/2] btrfs: allocate additional SYSTEM space earlier Neutral llm-chunked-no-replies Awaiting Review

This patch addresses a performance issue in Btrfs where large file systems can accumulate thousands of system chunks, leading to slow deletion of unused block groups when the file system is filled up and then rapidly emptied. To fix this, the patch allocates additional system space earlier by introducing a new function `system_space_needed` that estimates the upper bound on bytes needed to modify every leaf in the chunk tree. This allows for more efficient deletion of unused block groups, reducing the likelihood of aborting transactions due to lack of space.

[PATCH 2/2] btrfs: commit after deleting an unused block group if system space is low Neutral llm-chunked-no-replies Awaiting Review

This patch addresses a problem where deleting multiple unused block groups in one transaction can fail due to insufficient system space, resulting in an -ENOSPC error. To solve this issue, the patch introduces a mechanism that checks for low system space and commits a single transaction to delete a single block group at a time. This approach allows the system to recover unallocated space and improves the chances of successfully allocating system chunks. The patch modifies the btrfs_delete_unused_bgs function in fs/btrfs/block-group.c to implement this new behavior.

Last comment 2026-09-23 [PATCH v1] btrfs: add LOGICAL_INO_V2 flag for avoiding the tree modification log Positive LLM (per-reviewer) Accepted

This patch adds a new flag, LOGICAL_INO_V2, to the Btrfs file system that allows userspace to avoid enabling the tree modification log during backref walks. This is useful for applications like Meta's space usage estimation tool, which can tolerate slightly stale results and doesn't need the full accuracy of the tree modification log. The patch introduces a new ioctl argument, BTRFS_LOGICAL_INO_ARGS_COMMIT_ROOT, that enables this behavior by making the walk use commit roots instead of current trees. This reduces the overhead on the file system during transactions and allows userspace to choose between accuracy and performance.

Ongoing Submitted 2026-09-21 🔥 TODAY [PATCH 2/2] mm: page_alloc: remove ALLOC_NON_BLOCK from ALLOC_RESERVES Needs Work LLM (per-reviewer) Under Review

This patch removes the ALLOC_NON_BLOCK flag from the ALLOC_RESERVES definition in the Linux kernel's page allocation code. The flag was previously used to grant access to a reserve of memory below the minimum watermark, but this caused issues when GFP_NOWAIT allocations were made under memory pressure. By removing the flag, the patch prevents direct reclaim and stalls during such bursts, ensuring that high-order atomic allocations are not disrupted by GFP_NOWAIT consumers. The patch also updates comments in the code to reflect the correct behavior of ALLOC_NON_BLOCK.
