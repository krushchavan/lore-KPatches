[PATCH v3] mm: remove min_free_kbytes adjustment for THP

View on lore.kernel.org →
Submitted: 2026-09-01
Active on: 2026-09-01
Patch summary
This patch removes the adjustment for minimum free kbytes (min_free_kbytes) when Transparent Huge Pages (THP) are enabled. The current implementation adjusts min_free_kbytes to accommodate 512M pageblocks, but this can lead to issues such as increased fragmentation, reduced conversion rates, and poor performance on smaller machines. By removing this adjustment, the patch aims to address a deeper problem of oversized pageblock sizes, which can cause problems even when min_free_kbytes is set correctly.
Zi Yan 2026-09-01 Reviewed-by Needs Work LLM
Reviewer Zi Yan questioned why a large pageblock would still result in many fallbacks, suggesting it indicates a problem with unmovable pages being allocated and remaining free across multiple pageblocks, and asked for elaboration on how larger pageblocks cause bigger issues. Reviewer noted that the excessive min_free_kbytes is a symptom of an underlying issue with the anti-fragmentation mechanism, which fails to work as expected and requires high min_free_kbytes for khugepaged to function; they suggested exploring alternative solutions such as watermark boost or reclaiming extra free memory instead of reserving it via min_free_kbytes Reviewer noted that the patch's assumption of 'set and forget' min_free_kbytes recalculation does not hold true for khugepaged code, which recalculates it whenever THP/mTHP/shmem THP enablements change.
