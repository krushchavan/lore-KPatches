[PATCH] memcg: Don't call schedule_work when no spinning is allowed

View on lore.kernel.org →
Submitted: 2026-08-31  ·  Last comment: 2026-09-01
Active on: 2026-09-01 • 2026-08-31
Patch summary
This patch modifies the memcg (memory cgroup) code to prevent unnecessary work scheduling when spinning is not allowed, simplifying the done_restock code path by returning early instead of adding complexity.
David Stevens 2026-08-31 Reviewed-by Needs Work LLM
Reviewer David Stevens noted that he found the issue via code inspection and was unable to trigger it in real-world scenarios, except by writing a hacky driver using alloc_pages_nolock(). He suggested instead of adding complexity, simply returning if spinning is not allowed on the done_restock path. Reviewer David Stevens noted that returning from the done_restock path without triggering memcg reclaim could lead to missing MEMCG_HIGH events, which he considers a more serious issue than dropping userspace notifications.
