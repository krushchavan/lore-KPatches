Patch summary
This patch fixes a null pointer dereference in the hugetlb_cma_alloc_frozen_folio function by changing its behavior when encountering a NULL nodemask. Instead of falling back to all N_MEMORY nodes, it will now fall back to the task's hardwall cpuset, as defined by &cpuset_current_mems_allowed. This change ensures that memory allocation policies are respected even in the presence of a NULL nodemask.
Sourav Panda 2026-08-06 Inline Review Reviewed-by Needs Work LLM
Reviewer Sourav Panda noted that the current implementation of hugetlb_cma_alloc_frozen_folio() allows fallback to all N_MEMORY nodes when a NULL mempolicy mask is encountered, which does not align with the task's hardwall cpuset. He suggested replacing nodemask = &node_states[N_MEMORY]; with a call to read_mems_allowed_begin() and cpuset_current_mems_allowed to determine the allowed memory nodes.
