Patch summary
This patch series reduces contention on loads in the zswap compression system by introducing separate requests and mutexes for compression and decompression, allowing loads to no longer wait for stores. The second patch further optimizes synchronous decompression by using on-stack requests when possible, reducing lock contention even more. This results in significant performance improvements, with reads over 10ms falling from 26-35 per run to none with a single CPU and from 3-18 per run to at most one with eight CPUs.

The author acknowledged that loads no longer wait for stores due to separate requests, but explained that stores still serialize on the compression mutex and need more than a request, specifically mentioning the protection of the per-CPU PAGE_SIZE output buffer.
Show original comment 
Stores need more than a request. The compression mutex also protects
the per-CPU PAGE_SIZE output buffer, which has to stay ours until
zs_obj_write() copies it out, since zs_malloc() needs the compressed
length first. Loads stopped using that buffer in e2c3b6b21c77f, so an
on-stack request was enough for them, but the buffer is too big for
the stack.
