Patch summary
This patch fixes issues related to delegated timestamps in the NFSv4 protocol. Specifically, it addresses a problem where nfsd_setattr() waits for a delegation return while still holding the inode lock, which can cause the operation to time out and fail. The patch drops the inode lock during the wait period, allowing the file system to change while waiting for the delegation return. If the wait times out, the patch retries once before returning an error. This fix ensures that NFSv4 operations involving delegated timestamps are handled correctly and do not result in failed operations due to timing issues.

The author addressed a concern about nfsd_break_deleg_cb() running multiple times per lease, which causes cl_delegs_in_recall to be incremented but not decremented correctly. The author explained that this is due to the function being called directly by dir notification paths and lm_break, and provided a fix to skip incrementing cl_delegs_in_recall when dl_recalled is already set.
Show original comment 
nfsd_break_deleg_cb() can run more than once per lease:
- __break_lease() calls lm_break for a read breaker
  (FL_DOWNGRADE_PENDING) and again for a later write breaker
  (FL_UNLOCK_PENDING).
- nfsd_handle_dir_event() and nfsd_recall_all_dir_delegs() call
  nfsd_break_deleg_cb() directly, possibly repeatedly.

decrements it only once, at F_UNLCK. The leaked count keeps
nfs4_anylock_blockers() true, so the client can never again become a
courtesy client.

and the stores to dl_recalled and fi_had_conflict. All callers and the
F_UNLCK decrement run under flc_lock. Setting fl_break_time to 0, the
nfsd_break_one_deleg() call, and the false return stay unconditional.

Jeff Layton (author) 2026-11-23 Neutral LLM
The author addressed a concern about the potential for a client to be destroyed while waiting for a GETATTR reply, which could lead to a freed nfs4_client being accessed by nfsd4_put_stid(). The author explained that taking a client reference along with the delegation reference under flc_lock prevents this issue. A new function, nfsd4_get_leased_deleg(), is introduced to take both references, and nfsd4_put_leased_deleg() drops them when done.
Show original comment 
nfsd4_deleg_getattr_conflict() takes a reference on a write delegation
it finds through the inode's lease, sends CB_GETATTR, waits for the
reply, and drops the reference only after the wait.
nfsd4_encode_fattr4() can also hold the delegation until the GETATTR
reply is encoded.

A delegation reference doesn't keep its client alive. __destroy_client()
doesn't wait for stateid references, and the final nfs4_put_stid() uses
the client (cl_lock, the stateid idr and ->sc_free). If the client is
destroyed while the GETATTR waits, the GETATTR's put can touch a freed
nfs4_client. For example, a client that does not reply to the CB_GETATTR
can have its lease expire during the wait.

Under flc_lock, while the lease is still on the inode, take a client
reference along with the delegation reference. Client teardown removes
the lease before free_client() drops the client's initial reference, so
the client is still live while the lease is on the inode.
nfsd4_put_leased_deleg() drops both references.

Jeff Layton (author) 2026-11-23 Neutral LLM
The author addressed a concern about missing freeze protection for filesystems in certain NFSv4 delegation update paths, explained that the issue is due to the lack of superblock's freeze protection being held while updating timestamps, and provided patches to add freeze protection checks and notifications when trying to update timestamps on frozen filesystems.
Show original comment 
cb_getattr_update_times(), nfsd_update_cmtime_attr() and
nfsd4_finalize_deleg_timestamps() call notify_change() under
inode_lock(), but nothing holds freeze protection for the export's
filesystem. They can therefore modify a frozen filesystem. On ext4, a
foreign GETATTR whose CB_GETATTR finds that the holder modified the file
trips the WARN_ON() in ext4_journal_check_start(), and the inode's mtime
and ctime change while the filesystem is frozen.

The delegation's file (but see CB_GETATTR below) and the COPY or CLONE
destination are open for write, so the mount's write access is held.
Only the superblock's freeze protection is missing. Freeze protection is
taken outside inode_lock.

- cb_getattr_update_times() runs in the nfsd thread that is processing
  the GETATTR. Rather than hold the thread until the thaw,
  cb_getattr_update_times() tries for freeze protection and returns
  NFS4ERR_DELAY, so the client retries. The GETATTR's delegation
  reference doesn't keep the file open, though. A racing DELEGRETURN or
  revocation can put fi_deleg_file, so pin fi_deleg_file to keep the
  write access. Skip the update once the delegation is unhashed, because
  the delegation's return may already have finalized the times. The
  times from CB_GETATTR are older and would roll the finalized times
  back.
- nfsd_update_cmtime_attr(), from COPY and CLONE, waits for the thaw, as
  the data change that made the update necessary did.
- nfsd4_finalize_deleg_timestamps() runs when a delegation's lease is
  released, including from the laundromat and during NFSD shutdown.
  Neither path may wait for a thaw, so nfsd4_finalize_deleg_timestamps()
  only tries for freeze protection, and leaves the times alone with a
  notice when the filesystem is frozen.

The author addressed a concern about the correctness of delegating atime in read open requests, explaining that exclusive authority over atime or merging every read holder's times is needed to correctly delegate atime, which NFSD does not support. Show original comment 
A read open that wants delegated timestamps gets
OPEN_DELEGATE_READ_ATTRS_DELEG. Several clients can hold read
delegations at once, so delegating atime correctly would need exclusive
authority over atime or a merge of every read holder's times. NFSD
supports neither exclusive atime authority nor such a merge.

Grant OPEN_DELEGATE_READ instead. The want flag is a request, so
declining the attribute delegation complies with RFC 9754 section 5. The
XDR cases for OPEN_DELEGATE_READ_ATTRS_DELEG stay, since
open_delegation_type4 is on the wire.

Jeff Layton (author) 2026-11-23 Neutral LLM
The author addressed a concern about delegated timestamps being applied in the same nfsd_setattr() call as other attributes. They explained that this was causing problems, including EPERM for holders not owning the file and incorrect handling of ctime. The author proposed to decode time_deleg_access and time_deleg_modify into new fields in sa_iattr, apply the vetted times with notify_change(ATTR_FORCE) after nfsd_setattr() handles other attributes, and make changes to attrsset and nfsd4_secinfo_no_name_release().
Show original comment 
Delegated times were decoded into sa_iattr with ATTR_DELEG and applied
in the same nfsd_setattr() call as every other attribute. Problems:
- A holder that doesn't own the file gets EPERM. notify_change() checks
  ownership for explicit times, but under RFC 9754 the delegation
  stateid grants the authority to set the times.
- ATTR_DELEG applies to the whole iattr, so __nfsd_setattr() needs
  special ctime handling for the other attributes.
- If the times are rejected, attrsset can't report the attributes that
  were set.

Decode time_deleg_access and time_deleg_modify into new sa_deleg_atime
and sa_deleg_mtime fields. After nfsd_setattr() handles the other
attributes, nfsd4_deleg_set_times() applies the vetted times with
notify_change(ATTR_FORCE) and an iattr that holds only times:
- A times-only request skips nfsd_setattr() and the export's read-only
  and immutable checks that nfsd_setattr() makes, so call
  fh_verify(NFSD_MAY_SATTR) first.
- Leave ATTR_DELEG clear. nfsd_breaker_owns_lease() keeps the holder's
  own lease intact, and any other lease is broken.
- Keep vetting against dl_[amc]time. When the vetted mtime is applied
  but the delegated ctime is rejected, ctime now moves to the current
  time instead of staying put, because the inode's mtime did change.
- Set dl_setattr only after notify_change() succeeds, so a failed update
  doesn't skip the restamp on delegation return.

nfsd4_setattr() skips nfsd_setattr() for a request with only delegated
times. A request that sets both the plain and the delegated form of a
time gets NFS4ERR_INVAL. nfsd4_setattr() checks for that conflict, and
checks the stateid, only after the minor version's supported attributes.
A minor version without delegated times therefore gets
NFS4ERR_ATTRNOTSUPP for them.

attrsset keeps the non-time bits when the times step fails. A failure
inside nfsd_setattr() still reports nothing as set, because
nfsd_setattr() can't report a partial update.

Delegated times in CREATE and OPEN createattrs get NFS4ERR_INVAL.
RFC 9754 permits delegated times only in a SETATTR from a delegation
holder, and EXCLUSIVE4_1 already rejects them through
suppattr_exclcreat. A minor version that doesn't support delegated
times still gets NFS4ERR_ATTRNOTSUPP.

ATTR_DELEG no longer reaches __nfsd_setattr(), so drop its ATTR_DELEG
branch and always add ATTR_CTIME. Make commit_metadata() visible to
nfs4proc.c.

Jeff Layton (author) 2026-11-23 Needs Work LLM
The author addressed a concern about the NFS4ERR_DELAY error being reported when a GETATTR reply omits the SIZE attribute, which caused the waiter to mark the file as modified and report an incorrect size. The author added code to treat a reply without SIZE as failed in nfsd4_cb_getattr_done(), recalling the delegation instead.
Show original comment 
decode_cb_fattr4() zeroes ncf_cb_fsize and fills it in only if the
reply's bitmap includes SIZE. nfsd4_deleg_getattr_conflict() doesn't
look at that bitmap. For a reply without SIZE, a non-empty file's size
doesn't match zero, so the waiter marks the file modified and sets
ncf_cur_fsize to zero. GETATTR replies then report the file as empty to
every client but the delegation holder.

NFSD always requests SIZE in CB_GETATTR, and the holder may have changed
the size. Add ncf_cb_bitmap0 to hold word 0 of the reply's bitmap,
cleared when the callback is issued. In nfsd4_cb_getattr_done(), treat a
reply without SIZE as failed. The waiter then recalls the delegation, as
for any other CB_GETATTR failure.

A reply that omits CHANGE is left alone. The zero change attribute does
not match, so the waiter errs on the safe side and treats the file as
modified.

Fixes: c5967721e106 ("NFSD: handle GETATTR conflict with write delegation")
