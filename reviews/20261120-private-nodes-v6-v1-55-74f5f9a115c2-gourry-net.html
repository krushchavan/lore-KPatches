[PATCH 55/60] mm/memory_hotplug: online and offline private memory nodes

View on lore.kernel.org →
Submitted: 2026-11-20
Active on: 2026-11-20
Patch summary
This patch allows a driver to hotplug memory onto a private node at runtime by passing a feature mask through driver-managed hotplug. The patch rejects masks that are not valid according to the node_memory_features_valid() function. Memory joins a node only if it has the same feature mask as the node, and the node's features remain until all System RAM blocks are removed, even when ZONE_DEVICE memory keeps the node alive. This patch also introduces a new function can_claim_node_memory() that checks whether a node can claim its memory based on the provided feature mask.
Gregory Relay 2026-11-20 Neutral LLM
Reviewer noted that the patch does not check if a memory block belongs to multiple nodes before calling can_claim_node_memory(), which may lead to incorrect results.

From: "Gregory Price (Meta)" <gourry@gourry.net>

Allow a driver to hotplug memory onto a private node at runtime.

Pass a feature mask through driver-managed hotplug, and reject masks
that node_memory_features_valid() refuses.

Memory joins a node only with the same mask. The node's features hold
while any System RAM block remains (including offline blocks), and are
reset after the last one is removed, even when ZONE_DEVICE memory keeps
the node alive.

dax/kmem and the other hotplug callers pass NODE_MEMORY_FEAT_ALL, which
registers the node as N_MEMORY_COMMON.
