Patch summary
This patch series adds support for FEAT_NMI (NMI) feature on arm64 architecture. The problem it solves is a race condition where a CPU entering power-down idle state masks SDEI, causing other CPUs to hang in csd_lock_wait() when trying to send an interrupt. The approach taken is to either fix the firmware or modify the kernel to never signal a CPU with SDEI masked, by adding a handshake between the signalling CPU and the cpu_pm notifier.
Kiryl (Meta) (author) 2026-11-19 Neutral LLM
The author acknowledged that the sdei_event_signal() function returns -EAGAIN when a masked target is signaled, and explained how it handles this situation by sending an IPI to the CPU instead of SDEI. The author also provided patches to modify the arm64_backtrace_ipi() function to use the new sdei_block_signal() function.

Here is what I meant.

sdei_event_signal() refuses a masked target with -EAGAIN, and the
backtrace sends those CPUs the regular IPI. A PE that sees a signal on
its way stays out of the power-down state; the mask paths that cannot
fail wait for it, up to a millisecond.

On QEMU with TF-A minus the v2.13 check, masking a CPU through
cpu_pm_enter() and then signalling it gets -EAGAIN instead of the wedge,
and sysrq-l still goes over SDEI to the other CPUs.

I can send proper patches if it looks reasonable.
