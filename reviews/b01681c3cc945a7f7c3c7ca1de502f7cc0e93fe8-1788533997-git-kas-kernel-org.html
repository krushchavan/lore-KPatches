Show original comment 
Not as a member: khugepaged fills it once per pass from the sysfs knobs,
so there is no constant object to point at. And madvise has to
initialize it somehow after cc is allocated.

It could become a const pointer to a struct the caller owns, but that
adds a lifetime to track for a struct that is written in one place and
read everywhere else.  I would rather keep it embedded.

Kiryl Shutsemau (author) 2026-09-07 Neutral LLM
Author addressed reviewer Baolin Wang's concern about the strict_sub_pmd flag, explaining that it is already decided elsewhere in the code and should not be duplicated as a separate flag. The author agreed to keep the existing implementation.
Show original comment 
I would rather keep strict_sub_pmd.

Which orders a caller asks for is already decided elsewhere:
collapse_possible_orders() hands khugepaged every anonymous order and
MADV_COLLAPSE the PMD order only, from tva_type.

A flag called allow_mthp_collapse next to that would read as
a second place deciding the same thing, and flipping it would not change
which orders get collapsed.  What it does change is how a sub-PMD window
is judged once one is asked for, and it is read at exactly the three
places that judge one.

I will do:

      /* Take no swapped-out or shared PTE into a sub-PMD collapse */
      bool strict_sub_pmd;
