[PATCH 00/10] treewide: switch to __nonnull_args() macro

Active on: 2026-10-29 • 2026-10-28
Patch summary
This patch series replaces open-coded uses of the __attribute__((nonnull)) macro with the __nonnull_args() macro, which is a wrapper that keeps the quirks of the attribute in one place. The goal is to standardize nonnull attribute usage across the Linux kernel tree. The patches can be applied separately and are build-tested on various configurations. Some instances of __attribute__((nonnull)) remain in the tools subdirectory and should be updated separately after this patchset lands.
Dmitry Ilvokhin (author) 2026-10-28 Positive LLM
Author addressed a concern about kernel-doc warnings by adding support for __nonnull_args() as a function transform, which is a preparatory change for the treewide migration from __attribute__((nonnull)) to __nonnull_args().

Just to add a bit more colour to Miguel's reply.

I believe idea behind include/linux/compiler_attributes.h is to make
attribute wrappers as simple and transparent to use as native compiler
attributes. In particular, this means they should be available in every
kernel compilation unit without any additional effort.

For this reason, all the nessesary plumbing is handled at the build
machinery level (see scripts/Makefile.lib:171), where '-include'
compiler flag is used to pull in include/linux/compiler_types.h, which
in turn pulls include/linux/compiler_attributes.h.
