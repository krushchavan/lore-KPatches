[PATCH 05/60] mm/mempolicy: keep interleave and tmpfs mount policies on common memory

View on lore.kernel.org →
Submitted: 2026-11-20
Active on: 2026-11-20
Patch summary
This patch modifies the Linux kernel's memory policy module to use a new concept called N_MEMORY_COMMON when calculating boot policies and their per-node sysfs entries. It restricts the node set for mpol_set_nodemask() and mbind() masks to only include nodes that are part of N_MEMORY_COMMON. Additionally, it updates tmpfs and interleave policies to default to common memory nodes if no specific nodelist is provided. This change aims to simplify policy management by limiting the scope of certain policies to a smaller set of nodes.
Gregory Relay 2026-11-20 Reviewed-by Neutral LLM
Reviewer Gregory Relay noted that the patch incorrectly uses N_MEMORY_COMMON instead of N_MEMORY in several places, including for_each_node_state() loops and node_states[] checks, which could lead to incorrect behavior when dealing with non-common memory nodes.

From: "Gregory Price (Meta)" <gourry@gourry.net>

Use N_MEMORY_COMMON for boot mempolicy calculations and their per-node
sysfs entries (weighted interleave weights).

Restrict the node set mpol_set_nodemask() applies to set_mempolicy()
and mbind() masks to N_MEMORY_COMMON nodes.

A tmpfs mpol= nodelist must name only N_MEMORY_COMMON nodes, and an
interleave policy without a nodelist defaults to them.

Later when an N_MEMORY node is omitted from the N_MEMORY_COMMON set,
they will be stripped from mempolicy nodemasks as they're not eligible
(similar to memoryless nodes today).

Signed-off-by: Gregory Price (Meta) <gourry@gourry.net>
