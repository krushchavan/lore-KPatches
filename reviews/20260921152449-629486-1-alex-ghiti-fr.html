[PATCH] mm: madvise: drop MADV_PAGEOUT folios at swap writeback completion

View on lore.kernel.org →
Submitted: 2026-09-23  ·  Last comment: 2026-09-24
Active on: 2026-09-24 • 2026-09-23
Patch summary
This patch improves the handling of MADV_PAGEOUT folios on asynchronous swap devices by marking them as dropbehind at isolation time instead of waiting for writeback completion. This allows the memory to be freed earlier, reducing latency and improving performance. The patch also updates various kernel modules to handle the new behavior correctly.
KunWu Chan 2026-09-24 Inline Review Reviewed-by Needs Work LLM
Reviewer KunWu Chan questioned whether the early accounting for PAGE_DROPBEHIND addresses over-reclaim in the MADV_PAGEOUT path, specifically highlighting that nr_reclaimed does not increase while anon folios remain under writeback, and suggested checking this with a delayed swap device such as dm-delay.

Alex, One question about the `nr_reclaimed` accounting.

`PAGE_DROPBEHIND` increments `nr_reclaimed` when the write is
submitted, while the folio may still be under writeback and is only
actually removed from the swap cache when writeback completes.

Kairui pointed out that async swap can over-reclaim because
`nr_reclaimed` does not increase while anon folios remain under
writeback. Does the early accounting for `PAGE_DROPBEHIND` address
that over-reclaim mechanism for this `MADV_PAGEOUT` path?

It might also be useful to check this with a delayed swap device, such
as the `dm-delay` case Kairui mentioned.
