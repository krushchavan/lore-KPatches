[PATCH 0/6] kernfs: stop taking kernfs_iattr_rwsem for writing in mkdir/rmdir

View on lore.kernel.org →
Submitted: 2026-11-20
Active on: 2026-11-20
Patch summary
This patch series addresses a performance issue in the Linux kernel's kernfs subsystem by reducing unnecessary locking during mkdir and rmdir operations. The current implementation holds multiple locks, including kernfs_iattr_rwsem, which can lead to host-wide stalls under memory and CPU pressure. The patches remove the write lock on kernfs_iattr_rwsem for these operations, as it is not necessary for most cases. Instead, other mechanisms such as seqlocks and inode setup are used to ensure consistency. As a result, mkdir and rmdir latency is significantly reduced, with improvements in both VM and physical host environments. The patches also improve the performance of stat() and access() operations on paths with iattrs.

Hi Shakeel,

I'd like to ask for some code comments / documentation.

This lockless read relies on two rules for kn->flags... the type bits
and flags set before publication never change, and the other flags are
only changed with kernfs_rwsem held for write (except KERNFS_NS).

Parts of this are explained in a comment in kernfs_dop_revalidate()
but not on the field, and that comment doesn't cover KERNFS_HIDDEN or
KERNFS_SUICIDAL/SUICIDED.

Since this series adds a lockless reader that depends on these rules,
how about a comment on kernfs_node->flags like:

/*
 * Type bits, flags set before publication, and KERNFS_NS are stable;
the rest change under
 * kernfs_rwsem (write).  Lockless readers of changing flags must use
READ_ONCE(), taking
 * one snapshot if they also test stable bits.
 */
