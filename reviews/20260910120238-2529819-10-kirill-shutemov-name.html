Patch summary
This patch removes the collapse_single_pmd() function and instead open-codes it in its two callers, khugepaged's walk and madvise_collapse(). The function is responsible for collapsing a single PMD by scanning under the lock held by the caller and then giving up the lock before running the collapse. The patch maintains the same locking behavior as before and does not introduce any functional changes.

The author addressed a concern about performance overhead, explaining that the current patch's approach (mmap lock/unlock and VMA revalidation) would dominate the cost in scenarios where memory is mostly huge, and instead suggests maintaining the original ratio of scans to runs. The author acknowledged that the patch will report a drop of the lock for huge pages, which is not desired, and agreed to restructure in v2.

The scan/run ratio.

Once memory is mostly huge nearly every scan refuses, and a refused
table is cheap: one pmd read for SCAN_PMD_MAPPED, one PTE walk under the
PTL otherwise.

In your version of the collapse loop, mmap lock/unlock plus VMA
revalidation would dominate the cost. It is not productive.

Note that scan in khugepaged is bounded by pages_to_scan so we would not
hog the lock.
