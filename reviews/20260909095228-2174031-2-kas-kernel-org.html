Patch summary
This patch adds a new module parameter called cmdq_max_n_shift to the iommu/arm-smmu-v3 driver, which allows users to cap the command queue depth as a log2 of the number of entries. The default value is zero, meaning the hardware maximum, but it can be set to any positive integer. The patch also introduces a helper function arm_smmu_queue_max_n_shift() that calculates the actual queue size based on the requested shift and the natural alignment of the IDR1 value. This change aims to provide more flexibility for systems with tight memory budgets or those driving a small number of devices, where the maximum queue depth is not necessary.

These names took me a while to figure out. Something like this seems
much clearer:

 hw_max_lg2
 ent_size_lg2
 user_limit_lg2

And the flow can be simplified alot:

static u32 arm_smmu_queue_max_lg2(u32 hw_max_lg2, u32 ent_sz_lg2,
				  u32 user_limit_lg2)
{
	u32 floor_lg2 = PAGE_SHIFT - ent_sz_lg2;

	if (is_kdump_kernel())
		return min(hw_max_lg2, floor_lg2);
	user_limit_lg2 = max(user_limit_lg2, floor_lg2);
	return min(hw_max_lg2, user_limit_lg2);

Just pass the MAX's as the user limit:

static inline u32 arm_smmu_evtq_max_n_shift(u32 ceiling)
{
	return arm_smmu_queue_max_lg2(ceiling, EVTQ_ENT_SZ_SHIFT,
				      EVTQ_MAX_SZ_SHIFT);
With only one min:

	return arm_smmu_queue_max_lg2(ceiling, CMDQ_ENT_SZ_SHIFT,
