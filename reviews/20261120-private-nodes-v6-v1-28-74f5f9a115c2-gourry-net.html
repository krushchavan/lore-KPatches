[PATCH 28/60] mm: select memory features per node

View on lore.kernel.org →
Submitted: 2026-11-20
Active on: 2026-11-20
Patch summary
This patch introduces the ability to select memory features per node in the Linux kernel. It adds a new field, `memory_features`, to the `pg_data_t` struct to store a bit mask indicating whether a node's memory is common or private. The patch also updates various functions and macros to handle this new feature, including node state publishing and validation. This change allows for more flexibility in managing memory features on a per-node basis, which can be useful in certain scenarios such as NUMA systems without node 0 holding all memory.
Gregory Relay 2026-11-20 Neutral LLM
Reviewer noted that node_memory_features_valid() is not called in the hotplug path when memory is onlined, potentially allowing invalid features to be set for a node.

From: "Gregory Price (Meta)" <gourry@gourry.net>

Whether a node's memory is common or private is a property of the
memory, so record it per node.

Add a per-node memory feature mask (pgdat->memory_features) with a
single bit for common memory. Node states are published from the node's
features at boot and when memory is onlined. A node without the common
bit joins N_MEMORY_PRIVATE.

Ordinary System RAM carries every feature. Without NUMA, node 0 holds
all memory, so a mask without common memory is invalid.

Every node keeps the default mask, so all memory remains common.
