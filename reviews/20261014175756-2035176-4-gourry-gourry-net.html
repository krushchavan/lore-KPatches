Patch summary
This patch adds four new tests to the selftests/mm/madvise test suite to verify the behavior of madvise(2) when dealing with zero-length ranges, unaligned start addresses, and unmapped gaps in the range. The tests check that a zero-length range is accepted, an unaligned start address is rejected, and an unmapped gap in the range causes either MADV_COLD or MADV_PAGEOUT to fail with ENOMEM. Additionally, the patch includes code to pin the test task to a specific CPU to ensure consistent behavior.
Gregory (Meta) (author) 2026-10-14 Neutral LLM
The author is addressing a concern that the patch's pin_to_current_cpu function fails on large systems due to sched_getcpu() returning a CPU number above CPU_SETSIZE, causing sched_setaffinity() to fail. The author proposes using CPU_ALLOC() to dynamically size the mask instead of relying on a fixed-size mask.

Sashiko fixup for patch 3/8

This is largely an overly aggressive fix for systems with >1024 cpus,
but it's simple enough and can just be squashed.

sched_getcpu() can return a CPU number at or above CPU_SETSIZE on large
systems. CPU_SET() ignores such a number, so the fixed-size mask stays
empty, sched_setaffinity() fails with EINVAL, and every test that pins
itself fails. Size the mask to the CPU number with CPU_ALLOC() instead.
