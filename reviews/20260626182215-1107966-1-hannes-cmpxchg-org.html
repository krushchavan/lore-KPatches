[PATCH 0/4] mm: fix reclaim storms in defrag_mode

View on lore.kernel.org →
Submitted: 2026-07-02  ·  Last comment: 2026-07-09
Active on: 2026-07-09 • 2026-07-02
Patch summary
This patch series addresses a performance issue in the Linux kernel's memory management system, specifically when vm.defrag_mode is enabled. The problem arises from non-movable requests spinning and reclaiming unproductively due to kswapd/kcompactd being overwhelmed. To fix this, the patches modify the allocator slowpath to allow non-movable requests to participate in pageblock production, which has been successfully tested on an affected workload for two weeks.
Vlastimil (SUSE) 2026-07-02 Inline Review Reviewed-by Needs Work LLM
Vlastimil noted that in defrag_mode, non-movable pages can be allocated into movable blocks without restrictions, but movable requests are not allowed to allocate into unmovable blocks until they become sync; he questioned whether this asymmetry is intentional and suggested it should be reflected in the code.
