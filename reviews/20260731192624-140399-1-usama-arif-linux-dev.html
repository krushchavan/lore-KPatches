[PATCH] futex: Avoid hash-bucket locking for mismatched waits

View on lore.kernel.org →
Submitted: 2026-08-10
Active on: 2026-08-10
Patch summary
This patch modifies the futex_wait_setup function to read the futex word before taking the hash bucket lock, reducing contention and improving performance. The change allows for a precheck of the futex value without acquiring the lock, which is particularly beneficial in scenarios where the futex words are frequently mismatched. This approach also simplifies the code by removing unnecessary lock acquisitions and waiter accounting operations. By avoiding hash-bucket locking for mismatched waits, the patch aims to reduce contention and improve overall system performance.

Author acknowledged a potential performance issue related to STAC/CLAC instructions on older Zen CPUs, but noted that Zen 5's AC renaming improves their performance and is not a memory-ordering instruction like LFENCE. Author responded to concerns about the patch's performance impact, explaining that a deliberately modified version of futex_wait_timeout.c shows no wall-time regression and that the extra userspace read does not cause contention or additional work under lock.
