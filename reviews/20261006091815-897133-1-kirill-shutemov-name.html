[PATCH v2] mm: page_alloc: make defrag_mode retries follow the promoted order

View on lore.kernel.org →
Submitted: 2026-10-06  ·  Last comment: 2026-10-07
Active on: 2026-10-07 • 2026-10-06
Patch summary
This patch modifies the behavior of page allocation in defrag_mode to make retries follow the promoted order, rather than the original request order. This change is intended to prevent indefinite retrying by requests that are not movable, which can lead to high memory pressure and OOM killing. The patch also updates the retry logic for direct reclaim and compaction to take into account the promoted order, and resets the retry counters when a fallback attempt is made. As a result of this change, the number of should_reclaim_retry() calls and peak memory pressure are significantly reduced, leading to improved system performance.
Andrew Morton 2026-10-06 Reviewed-by Neutral LLM
Reviewer Andrew Morton questioned whether the patch should be applied to stable and 7.3-rcX kernels due to its size, suggesting caution before applying such a large change.

Show original comment 
Should these counters be reset only when the work order was actually
promoted?

For movable requests, and requests already at or above pageblock
order, `reclaim_order == order`. Their retry budget was therefore
spent on the request itself rather than on promoted pageblock
production. Resetting the counters here can give those requests
another 17 no-progress reclaim attempts, plus additional
compaction-success retries, before OOM or allocation failure.

How about:
	if (reclaim_order != order) {
		no_progress_loops = 0;
		compaction_retries = 0;
	}

instead?
