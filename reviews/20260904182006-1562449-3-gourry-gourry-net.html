[PATCH 2/2] sched/numa: scan read-only file mappings in tiering mode

View on lore.kernel.org →
Submitted: 2026-09-04
Active on: 2026-09-04
Patch summary
This patch series addresses an issue in memory tiering where read-only file-backed mappings are not being scanned, leading to inefficient promotion of pages. The patch introduces a new function `vma_is_ro_file` to identify such mappings and modifies the `task_numa_work` function to scan these VMAs with the slow_only restriction. This ensures that only non-toptier folios are made hint-faultable, preventing unnecessary rescanning.

Sashiko thinks this causes unneeded rescanning, but I don't think it
does. The cursor prevents it from restarting, and when we loop back
around reset_ptenuma_scan() bumps the sequence.

It also had concerns about concurrent scanners and ptl lock contention,
but mm->numa_next_scan only admits one per scan period.

Either way on a rewalk the scan hits pte_protnone() and moves on.
