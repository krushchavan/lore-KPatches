[PATCH v2 1/5] btrfs: use an on-stack path in btrfs_insert_orphan_item()

View on lore.kernel.org →
Submitted: 2026-08-04  ·  Last comment: 2026-08-05
Active on: 2026-08-05 • 2026-08-04
Patch summary
The patch series aims to optimize memory allocation in the btrfs_insert_orphan_item() function by allocating a small struct on the stack instead of dynamically, reducing the risk of transaction aborts due to memory failures.

\u5728 2026/8/5 01:14, Jeff Layton \u5199\u9053:
> btrfs_insert_orphan_item() allocated a btrfs_path with btrfs_alloc_path()
> which returns -ENOMEM on failure. It is called from btrfs_orphan_add(),
> so a path allocation failure there turns a recoverable error into a
> transaction abort.
> 
> btrfs_path is only ~112 bytes, so allocate it on the stack instead.
