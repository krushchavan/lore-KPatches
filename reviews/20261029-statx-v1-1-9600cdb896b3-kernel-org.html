[PATCH] statx: don't leak STATX_ATTR_CHANGE_MONOTONIC in stx_attributes_mask

View on lore.kernel.org →
Submitted: 2026-11-02
Active on: 2026-11-02
Patch summary
This patch fixes a bug in the statx system call where kernel-internal attribute STATX_ATTR_CHANGE_MONOTONIC is leaked to userland on filesystems that advertise it. The fix involves masking out this attribute from stx_attributes_mask in cp_statx().

On Thu 29-10-26 12:20:27, Jeff Layton wrote:
> STATX_ATTR_CHANGE_MONOTONIC is kernel-internal. cp_statx() strips it
> from stx_attributes but copies attributes_mask verbatim, so it leaks to
> userland on filesystems that advertise it (nfs, ceph), e.g.
> stx_attributes_mask = 0x8000000000b03000 on NFS.
> 
> Mask it out of stx_attributes_mask too.
