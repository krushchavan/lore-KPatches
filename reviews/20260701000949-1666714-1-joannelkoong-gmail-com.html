Patch summary
This patch series converts the iomap code to use an iterator model, replacing the legacy ->iomap_begin() and ->iomap_end() interface. The conversion is mechanical, with no functional changes intended. The new ->iomap_next() interface allows filesystems to provide direct begin/end helper functions, which are then used by the iomap_process() inline helper. The patches also update the documentation to reflect the new iterator model.
Joanne Koong (author) 2026-07-02 Positive LLM
Author Joanne Koong addressed a concern about naming consistency in iomap_next() functions, agreeing that renaming to iomap_iter() would make the purpose of these functions more explicit. She plans to make this change for v3.
