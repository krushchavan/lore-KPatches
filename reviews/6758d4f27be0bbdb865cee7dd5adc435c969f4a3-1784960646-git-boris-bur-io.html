Patch summary
This patch modifies the Btrfs file system to trigger cow (copy-on-write) fixup via dirty_folio(). The change aims to improve handling of delalloc lookup and reservation in the presence of subpage folios, which are not expected to have fixup bits. It also removes vestigial code related to ordered operations and reworks the implementation to handle potential TOCTOU (time-of-check-to-time-of-use) races. The patch introduces a new approach to reserve the whole range and then free parts that don't end up in the 'funded' bitmap, which is considered an improvement over the previous implementation.
Boris Burkov (author) 2026-07-25 Needs Work LLM
Author acknowledged that some invariants were not properly trimmed from the LLM-generated code and agreed to rework them. Author acknowledged that the delalloc lookup is essential for distinguishing between re-dirtying and true fixups, but is considering simplifying the code by removing the possibility of re-dirtying in typical cases. Author acknowledged that the code to check if ordered extent is present is unnecessary and agreed to simplify the logic by removing or hiding it, depending on the configuration. The author acknowledged a minor issue with technical terminology and promised to correct it. Author acknowledged a concern about the complexity of the proposed fixup worker and its potential for 'word salad' code, but did not indicate plans to revise or restructure the patch. Author acknowledged a potential issue where aops->dirty_folio() is called without locking the folio, but believes the current implementation's strategy of reserving the whole range and then freeing parts that don't get 'funded' should handle cancellations correctly. However, they acknowledge it's an ugly solution and consider an alternative approach with locking to be appealing but potentially flawed due to a TOCTOU race. Author acknowledges that avoiding the 'bfs->reserving_dirty' approach is a good idea and seems open to revising their patch, but doesn't explicitly state they will make changes. Author agrees that using dirty_folio() is an improvement, acknowledges current implementation as a 'stupid way' that introduces unnecessary risk, but does not indicate plans to revise the patch.

Qu Wenruo 2026-07-25 Inline Review Reviewed-by Needs Work LLM
Reviewer Qu Wenruo noted that the patch does not properly handle the case where a dio read is in progress and btrfs finishes writing back the folio, causing the dio to re-dirty the folio unnecessarily. They requested that the dirty_folio() call be moved after the folio is unlocked. The reviewer is concerned that the patch's complexity and size are overwhelming due to its rapid development by an LLM, which may lead to issues in review and maintenance. Reviewer Qu Wenruo noted that the call to trigger cow fixup via dirty_folio() is very frequent and redundant, suggesting that it can be merged into btrfs_folio*_set_dirty(), which ensures proper dirtying and cancellation of the fixup. Reviewer Qu Wenruo suggested simplifying the dirty_folio() check by only verifying if the fixup bit is not set, as this indicates that the folio has gone through regular write preparation and should have EXTENT_DELALLOC. Reviewer Qu Wenruo suggested replacing the use of btrfs_is_subpage() and related functions from subpage.c with a custom helper function, btrfs_folio_test_fixup(), to improve code readability. The reviewer noted that if a folio has already been dirtied properly, calling ->dirty_folio() may trigger a false alert because there might be no ordered extent (OE) created yet for the folio, violating one of the critical invariants. Reviewer Qu Wenruo suggested simplifying the code by skipping ordered extent (OE) lookup and letting the final submission path handle it, citing a recent patch that achieves similar functionality at submission time. Reviewer Qu Wenruo expressed concern about the variable naming in the patch, stating that it appears to be generated by a Large Language Model (LLM) and may require additional explanation for non-native speakers. Reviewer Qu Wenruo questioned whether triggering cow fixup via dirty_folio() is necessary because the folio has not yet been dirtied, and expressed uncertainty about the need for this patch. Reviewer Qu Wenruo suggested using btrfs_folio_clear_fixup() instead of the proposed fix to trigger cow fixup via dirty_folio(), indicating that their preferred approach is more helpful. Reviewer Qu Wenruo expressed frustration with the LLM's comments and suggested deleting them by default, implying that they are unnecessary or unhelpful. The reviewer, Qu Wenruo, pointed out that the patch can lead to over-reservation of space for already properly dirtied ranges, making it impossible to release reserved space without clearing qgroup flags. This issue is difficult to expose through tests because dirty folios are hard to trigger. Reviewer Qu Wenruo suggested using a proper btrfs_folio_clear_fixup() function to handle the loop, passing in the folio range instead of relying on dirty_folio(). Reviewer Qu Wenruo pointed out that the patch's approach to handling dirty folios via dirty_folio() is unnecessary, as regular btrfs_folio_clear_dirty() can handle all these cases and there's no need for a special subpage branch. Reviewer Qu Wenruo questioned the necessity of using dirty_folio() when folio_test_dirty() would be sufficient, specifically pointing out that the subpage part does not have this check. Reviewer Qu Wenruo noted that calling folio_mark_dirty() would lead to a recursive call to ->dirty_folio(), and instead implemented a local version of filemap_mark_dirty() to set the fixup bits. The reviewer noted that the patch may not fully address the COW fixup issue, suggesting that additional checks are needed to ensure that the last fixup bit is cleared and the folio fixup flag is reset. Reviewer Qu Wenruo suggested that the btrfs_page_ops implementation should handle all fixup helpers, rather than relying on a separate dirty_folio() function. Reviewer Qu Wenruo noted that since btrfs_folio_set_dirty() does not call folio_mark_dirty(), the fixup bit is not actually being set, and suggested removing the dirty_folio() call to skip setting the fixup bit.
