Patch summary
This patch proposes a new approach to trigger the COW (Copy-On-Write) fixup in Btrfs via the dirty_folio() function, which is used to handle folios that have been improperly dirtied during writeback. The current implementation uses an asynchronous worker to catch and fix such cases, but this patch aims to simplify the process by leveraging the dirty_folio() function. This change addresses a long-standing issue where a dio read may skip dirtying a folio if it is already clean by the end of the I/O operation, leading to potential data corruption. The patch maintains three critical invariants to ensure that each block is written exactly once: any dirty block is covered by delalloc or an ordered extent, any dirty block submitted into an OE will be written back within that OE, and any dirty block already submitted into an OE will not be resubmitted. This change aims to demonstrate a more complex solution to the problem and highlight the issues it must address.

Qu Wenruo expressed concerns that the assumption in btrfs_folio_lock() about the relationship between dirty folios and ordered extents is incorrect, potentially causing false alerts when ->dirty_folio() callback is triggered for properly dirtied blocks. He suggested simplifying the check to just verify if the fixup bit is not set.
