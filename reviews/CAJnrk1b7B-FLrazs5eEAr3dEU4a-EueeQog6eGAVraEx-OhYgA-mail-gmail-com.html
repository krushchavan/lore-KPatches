Patch summary
This patch consolidates the logic for creating and updating the mapping of queues to CPU IDs in the FUSE (Filesystem in Userspace) implementation of io-uring. The current approach has two separate flows for legacy and dynamic queue paths, which are merged into a single flow. In this new flow, the mapping is updated on the first registration of a queue, and it's built from the global registered queue mask. This change also fixes an issue where requests mapped to a queue could get lost if there was a failure between adding the queue and registering its first entry. Additionally, the patch allows dynamic queues to be advertised, which enables rejecting qids that don't map to possible CPU IDs during ADD_QUEUE.
