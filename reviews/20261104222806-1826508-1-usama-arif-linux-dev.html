[PATCH v2] x86/lib: Use REP MOVSB for large memcpy() on ERMS CPUs without FSRM

View on lore.kernel.org →
Submitted: 2026-11-04  ·  Last comment: 2026-11-10
Active on: 2026-11-10 • 2026-11-05 • 2026-11-04
Patch summary
This patch optimizes large memory copies on ERMS CPUs without FSRM by using the REP MOVSB instruction from 2048 bytes onwards, reducing execution time by up to 66.8%. The patch also folds memcpy_orig() into __memcpy() and makes adjustments for FSRM CPUs. Smaller copies continue to use a scalar loop for performance reasons.
Usama Arif (author) 2026-11-05 Neutral LLM
The author addressed a concern about the patch's applicability to specific CPU models by confirming that Zen 1 and Zen 2 do not have ERMS or FSRM, thus keeping the scalar loop, while Zen 3 onwards use REP MOVSB for every size. Author acknowledges that using REP MOVSB for small copies might be beneficial but wants to prioritize the current usecase-driven approach from zstd/btrfs. The author clarifies that the performance issue with REP MOVSB on misaligned copies between 512 and 640 bytes was due to specific alignment, not a general problem with using REP MOVSB at this threshold. Author agrees that the current patch is acceptable, but suggests investigating further if a use case for smaller sizes can be found.

David Laight 2026-11-10 Inline Review Reviewed-by Needs Work LLM
Reviewer David Laight noted that the patch does not handle the case where the length is a power of two, which can result in slower performance due to the shift operation used for ERMS CPUs. Reviewer David Laight expressed concern about the alignment of the FSRM replacement, suggesting it should be aligned to avoid performance issues when the RET instruction is in the first half of a cache line. The reviewer expressed concern about the added jump instruction on non-FSRM CPUs, suggesting it could have a measurable impact on performance in cold cache scenarios, but noted that this would only be an issue if RET is not always 0xc3. Reviewer David Laight suggested that the patch could be improved by avoiding unnecessary register-register moves and instead using a simple backtrack to get the value where it is needed, criticizing GCC for being bad at this optimization.
