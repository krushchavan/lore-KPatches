[PATCH RFC] mm/zswap: reference the pool by index to shrink struct zswap_entry

Active on: 2026-07-28 • 2026-07-27
Patch summary
This patch modifies the zswap compression algorithm to reference its pool by index instead of dynamically creating a new one for each algorithm, which is usually only one or two algorithms are actually used.

Jianyue Wu 2026-07-28 Reviewed-by Needs Work LLM
Reviewer Jianyue Wu noted that the current implementation creates a new pool only when setting a new compression algorithm, which is usually just one or two algorithms in practice, and suggested that 16 pre-allocated pools are already sufficient for this purpose. The reviewer ran e2e benchmark tests comparing baseline and the RFC patch, but did not observe a measurable performance regression, instead noting that certain compression algorithms (zswap crypto-sg zstd and lzo) are slower than others. Reviewer Jianyue Wu prefers to drop the xarray and use a fixed-size array of 16 entries, each indexed by a u8, allowing for runtime compressor switching while keeping the ability to increase the number of supported compressors as needed. Reviewer Jianyue Wu agreed that the dynamic list of compression algorithms is unnecessary complexity and offered to try dropping it; they also suggested considering dropping the obj_cgroup pointer on non-MEMCG systems, but deemed it not worth pursuing
