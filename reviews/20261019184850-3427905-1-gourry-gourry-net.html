[PATCH] mm/page_alloc: let the highest memory node recover from hopeless state

Patch summary
This patch fixes a problem where the highest memory node in a system cannot recover from a 'hopeless' state, even when its zone recovers above the high watermark. The issue arises because the current code checks if there is another memory node available for allocations to fall back to by looking at the next higher-numbered node ID, which always returns false for the highest node. This patch changes the check to count the number of nodes with a state of N_MEMORY, effectively checking if any other node exists. As a result, the highest node can now recover from its hopeless state and kswapd will be re-enabled.
