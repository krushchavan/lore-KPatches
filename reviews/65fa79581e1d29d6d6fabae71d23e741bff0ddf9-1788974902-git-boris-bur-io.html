[PATCH] btrfs: downgrade the reflink source inode lock

View on lore.kernel.org →
Submitted: 2026-09-10
Active on: 2026-09-10
Patch summary
This patch modifies the Btrfs file system to downgrade the lock on the source inode during a reflink operation from exclusive to shared, reducing contention and improving performance. The change also adds a flag to indicate when an inode is being used as a reflink source, which allows direct I/O writes to take the VFS inode lock in shared mode instead of exclusive mode. This patch was tested with concurrent readers and writers and showed significant latency improvements.

You mean a direct IO read operation happening in parallel with a
reflink using the same file as a source right?
And reflinking the entire file?

Because we only take the VFS lock (rwsem in struct inode) for direct IO reads.

However during reads (both direct IO and buffered) we always lock the
extent range in the inode's extent io tree, and the reflink also locks
the range.
So taking the rwsem in shared mode won't help much unless we are not
reflinking the whole file and direct IO reads happen on a different
range.
I think that should be explicit in the change log.
