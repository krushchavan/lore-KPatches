[PATCH 52/60] mm: count memory with userspace placement as general purpose

View on lore.kernel.org →
Submitted: 2026-11-20
Active on: 2026-11-20
Patch summary
This patch modifies the Linux kernel's memory accounting to treat memory on nodes that can be used by userspace as general-purpose memory. This means that totalram_pages() and MemFree will count this memory, and it will also affect other metrics such as overcommit and OOM capacity. The patch introduces new functions common_free_pages() and common_file_pages() to accurately calculate the amount of free memory on these nodes. It also adjusts the calculation of global dirtyable memory to exclude private memory that serves only private bindings and migration.
Gregory Relay 2026-11-20 Neutral LLM
Reviewer Gregory Relay noted that the patch incorrectly uses common_free_pages() in global_dirtyable_memory(), which counts private memory as well, and suggested using nr_free_pages() instead to accurately count only free pages on common nodes.

From: "Gregory Price (Meta)" <gourry@gourry.net>

Userspace places ordinary data on N_MEMORY_MEMPOLICY nodes, and neither
the commit charge nor a task's RSS can tell nodes apart. Treat their
memory as general purpose: totalram_pages() and MemFree count it, and so
do the limits sized from them (overcommit, OOM capacity).

Other defaults sized from totalram_pages(), such as the zswap pool and
tmpfs sizes, also see the larger total, as they already do for memory
the kernel cannot allocate from in ZONE_MOVABLE.

Free memory on these nodes serves only private bindings and migration,
so counting it in MemAvailable or the global dirtyable memory would
overstate both. Add common_free_pages() and use it there.

MemAvailable also assumes about half of the file LRU can be reclaimed.
Reclaiming file pages on these nodes frees only private memory, so
count only the file LRU on common nodes, via common_file_pages().

File pages that reach a private node through migration stay covered
by the dirty limits' file LRU term.
