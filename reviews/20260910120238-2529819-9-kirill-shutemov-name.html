[PATCH v2 08/12] mm/collapse: separate scanning a PTE table from collapsing it

Active on: 2026-09-11 • 2026-09-10
Patch summary
This patch separates the scanning of a PTE table from collapsing it into two distinct functions: collapse_scan_pmd() and collapse_run_pmd(). The scan function reads the table under mmap_lock, while the run function performs the actual collapse. This change improves code organization and reduces complexity by separating these two tasks. Additionally, this patch introduces changes to tracing and khugepaged behavior, including new tracing events and adjustments to how file tables are handled.
Zi Yan 2026-09-10 Inline Review Reviewed-by Neutral LLM
Reviewer Zi Yan noted that the code has duplicate logic for setting scan_file to NULL, and suggested adding a helper function to avoid duplication. Reviewer Zi Yan noted that the result type is being changed from SCAN_SUCCEED to SCAN_PTE_MAPPED_HUGEPAGE, causing unnecessary result churn, and requested a way to avoid this. Reviewer Zi Yan suggested changing the return condition in collapse_run_pmd() to only handle SCAN_SUCCEED and SCAN_PTE_MAPPED_HUGEPAGE results, instead of all non-SCAN_SUCCEED results.
