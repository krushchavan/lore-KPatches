[PATCH 03/60] mm: introduce the common-memory node state

View on lore.kernel.org →
Submitted: 2026-11-20  ·  Last comment: 2026-11-22
Active on: 2026-11-22 • 2026-11-20
Patch summary
This patch introduces a new concept in the Linux kernel called 'common-memory nodes' to distinguish between nodes that have memory and those whose memory can be managed by the kernel's memory management services. The existing N_MEMORY flag is overloaded, so it now only indicates whether a node has memory, while a new flag N_MEMORY_COMMON is introduced for common-memory nodes. Userspace can identify these nodes using the 'has_common_memory' attribute. Additionally, documentation is updated to reflect these changes.
Gregory Relay 2026-11-20 Reviewed-by Neutral LLM
Reviewer noted that N_MEMORY is overloaded with two meanings, and requested the introduction of N_MEMORY_COMMON to mean nodes whose memory ordinary allocations may use without requesting the node explicitly, and that kernel memory management services manage.

From: "Gregory Price (Meta)" <gourry@gourry.net>

N_MEMORY is overloaded with two meanings:
  1) a node has memory.
  2) a node's memory is reachable via ordinary allocation or
     an arbitrary MM service may use that memory.

Allow N_MEMORY to mean #1, and introduce N_MEMORY_COMMON to mean #2.

N_MEMORY_COMMON nodes contain "common memory" capable of being managed
arbitrarily by the kernel MM based solely on zone membership. Following
commits convert relevant N_MEMORY users to N_MEMORY_COMMON.

Expose the state via `has_common_memory` so userspace can identify
the memory available to ordinary allocations and common MM services.

Add has_memory to the docs while we're here.

Signed-off-by: Gregory Price (Meta) <gourry@gourry.net>
