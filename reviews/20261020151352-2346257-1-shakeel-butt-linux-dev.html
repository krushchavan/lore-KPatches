[RFC PATCH] x86,resctrl: Read event counters with an IPI when the read cannot block

View on lore.kernel.org →
Submitted: 2026-10-26
Active on: 2026-10-26
Patch summary
This patch introduces a new configuration option CONFIG_RESCTRL_MON_READ_IRQSAFE to allow reading event counters with interrupts off on the current CPU or using an IPI when necessary. This is done to reduce long stalls caused by readers sleeping while holding rdtgroup_mutex, which can lead to gaps in monitoring data. The patch adds support for x86 architecture and provides results showing a significant reduction in hold time per read and time off CPU while holding the mutex.
Shakeel Butt (author) 2026-10-26 Needs Work LLM
Author acknowledged that the current implementation of CONFIG_RESCTRL_MON_READ_IRQSAFE does not handle the case where every CPU in the domain is nohz_full and agreed to add a check for this condition. Author acknowledged that a critical reader of the interface is experiencing multi-second stalls, which causes gaps in system observability, and agreed to address this issue. Author acknowledges the reviewer's concern about potential performance impact, but prioritizes avoiding critical daemons being stuck behind lower-priority readers. The author acknowledges that the patch does not address scalability issues, but explains that its purpose is to reduce hold time and uncertainty by changing how locks are held during sleeping. Author acknowledged the need to address the rate file interface and agreed to review Peter's prototype. Author acknowledges that some userspace applications may be impacted by the proposed change, but notes that other applications like below and dynolog read less often and are not as affected. Author acknowledges that the existing rate file tools are complementary to the mon_data files and agrees to address all reviewer suggestions in the next patch version.
