Patch summary
This patch adds API specification for sys_open, which is a common practice to document function contracts and ensure they remain up-to-date. The discussion highlights the trade-off between placing documentation in headers or separate files, but ultimately decides to keep it in the header for better visibility.

David Laight 2026-10-08 Reviewed-by Needs Work LLM
Reviewer David Laight expressed concern that the API specification for sys_open is placed in the .c file, which may lead to it becoming stale and out of sync with the code, and suggested keeping it in the header where it can be easily accessed by external users. Reviewer David Laight expressed concerns that documenting API contracts in comments within code files is not effective, as it would require updating both the code and the comments simultaneously, leading to bloat and potential inconsistencies. He suggested instead documenting return values at the C return statement.
