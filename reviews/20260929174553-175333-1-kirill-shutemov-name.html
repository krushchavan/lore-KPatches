[PATCH] mm: page_alloc: make defrag_mode retries follow the promoted order

Patch summary
This patch modifies the behavior of page allocation in defrag_mode to make retries follow the promoted order, rather than the original request order. This change is intended to prevent indefinite retrying by requests that are not movable, which can lead to reclaim storms and excessive memory pressure. The patch treats promoted requests as costly orders, resetting progress counters for them and checking compaction results at the promoted order. It also resets retry counters when a fallback attempt is taken, allowing it to get a full retry budget before the OOM killer is considered. This change aims to improve performance and reduce memory pressure in systems with high inode churn under memory.low protection.

killing the workload on sustained PSI, so PSI and the number of times
ALLOC_NOFRAGMENT gets dropped are the headline numbers. 32G VM, 8 CPUs:

 - fill memory with 4K anon pages in a cgroup, memory.low = fill + 1G,
   so page cache beyond that stays reclaimable;
