[PATCH 50/60] mm: add N_MEMORY_MEMPOLICY node state

View on lore.kernel.org →
Submitted: 2026-11-20
Active on: 2026-11-20
Patch summary
This patch adds a new internal node state called N_MEMORY_MEMPOLICY, which allows memory policy interfaces and explicit migration to target specific nodes. It also introduces a new feature flag NODE_MEMORY_FEAT_MEMPOLICY for memory providers to select this feature. The feature requires both reclaim and compaction of the node, and userspace placement can use the node like any other memory. This patch is part of a larger series of changes and is intended to improve NUMA control and memory management in Linux.

From: "Gregory Price (Meta)" <gourry@gourry.net>

Add N_MEMORY_MEMPOLICY as an internal state for the nodes that memory
policy interfaces and explicit migration may target, and
NODE_MEMORY_FEAT_MEMPOLICY for memory providers to select it.

Userspace placement lets ordinary processes use the node like any other
memory. That assumes the node is reclaimed and compacted, so the feature
requires both.
