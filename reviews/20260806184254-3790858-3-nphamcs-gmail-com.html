Patch summary
This patch adds support for virtual swap (vswap) in the Linux kernel, allowing pages to be compressed by zswap or detected as zero-filled without pre-allocating a physical swap slot. The vswap layer is built on top of the existing swap-table infrastructure and supports zswap and zero-page backends. A new sysctl /proc/sys/vm/vswap_enabled is added to enable or disable vswap allocation at runtime, defaulting off unless configured otherwise. Existing virtual entries will continue to resolve their backend and drain naturally when vswap is turned off.

Kunwu Chan 2026-08-20 Inline Review Reviewed-by Neutral LLM
Reviewer Kunwu Chan noted that a NULL dereference was reported in the v3 series, specifically due to the 'virtual_table' lifetime management introduced by this patch. Reviewer Kunwu Chan noted that vswap_free() acquires the per-vswap spinlock while holding the folio lock, creating a potential deadlock with reclaim paths when try_to_unmap() is called. Reviewer Kunwu Chan noted that using `atomic_long_read()` alone is insufficient to ensure the lifetime of the allocation being accessed, and requested additional synchronization Reviewer Kunwu Chan noted that the virtual_table introduced in this patch does not have an equivalent lifetime rule as the existing ci->table, which can lead to a NULL dereference when __vtable_get() is called after virtual_table has been torn down. He suggested making virtual_table follow the same lifetime scheme as the existing cluster table or tying its freeing to the lifetime of swap_cluster_info_dynamic.
