Patch summary
This patch adds support for moving PMD-level swap entries in UFFDIO_MOVE operations. It introduces a new function, move_swap_pmd(), which handles the movement of these entries under both PMD locks. The function propagates soft-dirty bits and arms the UFFD marker for an RWP-registered destination. It also revalidates the folio's association with the swap entry and updates the anon rmap metadata. The patch rejects a PMD swap entry at the destination with -EEXIST, as it is not a hole and does not resolve on its own. This patch addresses a problem where aligned UFFDIO_MOVE operations over swapped-out THPs fail due to the lack of support for PMD-level swap entries.
Lance Yang 2026-10-04 Inline Review Reviewed-by Neutral LLM
Reviewer Lance Yang noted that the move_swap_pmd() function does not properly handle the case where src_folio is NULL, and suggested adding a check for this condition to avoid potential crashes. Reviewer Lance Yang noted that the source UFFD marker should be cleared in move_swap_pmd() to maintain consistency with move_swap_pte(), which also clears the source UFFD marker. reviewer noted that move_swap_pmd() does not clear the source UFFD-WP marker before checking if the destination is registered for synchronous UFFD-WP, which could lead to unexpected behavior on swap-in and leave writers stuck Reviewer noted that move_swap_pmd() does not handle the case where src_folio is NULL, which can lead to a null pointer dereference when checking if it has been freed and reused for a different swap entry.
