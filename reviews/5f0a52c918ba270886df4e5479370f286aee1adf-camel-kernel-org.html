Patch summary
This patch fixes a bug in the Btrfs file system where the replace_task pointer is not properly cleaned up when a device replacement fails to start. The issue occurs because the dev_replace->replace_task pointer is left pointing to the task that started the replace, even if it failed. This can cause problems later on, such as stale pointers and potential rwsem releases. The patch fixes this by resetting the dev_replace->replace_task pointer in all error paths of btrfs_dev_replace_finishing().
Qu Wenruo 2026-08-13 Inline Review Reviewed-by Needs Work LLM
The reviewer pointed out that the patch incorrectly updates dev_replace->replace_task in btrfs_dev_replace_finishing(), leaving a stale pointer to the task that started the replace, which can cause issues when a later btrfs_dev_replace_start() assigns replace_task between reads of dev_replace->replace_task in btrfs_map_block(). The reviewer noted that taking the rwsem for read-only access to replace_task could reduce concurrency in btrfs_map_block(), and suggested replacing existing checks with a single comparison after acquiring the lock.

It turns out that, this is a complex false alerts.

There are several things here to ensure we won't get split lock/unlock 
behaviors:

- For tasks unrelated to replace
   They always get the replace_task mismatching current, and since the
   current task is already inside btrfs_map_block(), there is no way that
   the current task can run code to reassign replace_task.

   So even if replace_task is changed, it will never be changed to the
   current task, so we will still unlock the rwsem.

- For task which started the replace
   In that case, we are the task which called btrfs_dev_replace_start().

   However the only call site that re-assign replace_task is either
   btrfs_dev_replace_start() or btrfs_dev_replace_finishing() that I'm
   fixing.

   As long as btrfs_dev_replace_start() is fixed so that replace_task is
   not assigned to another task, we're safe.

   As btrfs_dev_replace_finishing() can only be reached by the running
   replace, which is the current task.
