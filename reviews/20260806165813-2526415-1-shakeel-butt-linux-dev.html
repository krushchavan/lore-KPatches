[PATCH v2] memcg: keep folio's objcg same as its node

View on lore.kernel.org →
Submitted: 2026-08-06
Active on: 2026-08-06
Patch summary
This patch introduces a helper function get_migration_objcg() that returns the objcg (object cgroup) associated with a folio, ensuring it is referenced and consistent across node boundaries. The function is used in mem_cgroup_replace_folio() to update page counters and charges correctly when replacing a folio. This change simplifies the code and ensures accurate accounting of memory usage.
Johannes Weiner (author) 2026-08-06 Needs Work LLM
Author acknowledged a concern about the behavior of get_migration_objcg() when there is a root mismatch, agreed that it must commit to the new objcg and explained how this affects the handling of page counters in mem_cgroup_replace_folio() and mem_cgroup_migrate(). The author provided a revised patch with the necessary changes.

+ * memcg_reparent_objcgs() reparents a dying cgroup one node at a time:

static struct obj_cgroup *get_migration_objcg(struct folio *old, struct folio *new)
{
	struct obj_cgroup *old_objcg, *new_objcg;
	int new_nid = folio_nid(new);
	struct mem_cgroup *memcg;

	old_objcg = get_obj_cgroup_from_folio(old);

	if (folio_nid(old) == new_nid)
		return old_objcg;

	memcg = obj_cgroup_memcg(old_objcg);
	new_objcg = __get_obj_cgroup_from_memcg(memcg, new_nid);
