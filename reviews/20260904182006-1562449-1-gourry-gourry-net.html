[PATCH 0/2] sched/numa: stop VMA scan filters from gating promotion

View on lore.kernel.org →
Submitted: 2026-09-04  ·  Last comment: 2026-09-07
Active on: 2026-09-07 • 2026-09-04
Patch summary
This patch series aims to stop VMA scan filters from gating promotion in the Linux kernel's scheduler and NUMA (Non-Uniform Memory Access) subsystem. The current implementation applies a series of VMA-level filters before marking a VMA for hint faults, which can lead to issues with memory tiering. The patches modify the per-VMA PID filter and read-only file mapping exclusion to allow promotion candidates to be added without removing existing filters.
Gregory Price 2026-09-04 Positive LLM
Addressed a double-put bug in fuse_try_move_page() and added an extra folio_get() before replace_page_cache_folio() to maintain the reference. Also, modified the per-VMA PID filter and read-only file mapping exclusion to allow promotion candidates to be added without removing existing filters.

> +				continue;
> +			}
> +			vma->numab_state->slow_only = true;
>  		}

sashiko (correctly) reported that slow_only=false set unconditionally
here causes a VMA that's scanned over two passes to be prematurely
re-admitted regardless of vma_is_accessed() activity.

Patch looks simple:

+               if (mm->numa_scan_offset <= vma->vm_start)
+                       vma->numab_state->slow_only = false;

and on patch two:

-                       vma->numab_state->slow_only = false;
+                       vma->numab_state->slow_only = ro_file;

I'll follow up with a v2 next week after I test it.

~Gregory
