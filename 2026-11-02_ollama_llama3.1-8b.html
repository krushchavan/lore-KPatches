🔥 TODAY [PATCH v4] mm: bypass swap readahead for zswap Positive LLM (per-reviewer) Under Review

This patch bypasses swap readahead for zswap, an in-memory, synchronous backend similar to zram. The current implementation of swap readahead is optimized for disk-based swaps and can cause unnecessary page cache thrashing and compression traffic when used with in-memory swaps like zswap. By bypassing readahead for zswap, the patch aims to reduce memory usage, improve performance, and decrease compression overhead. The results show significant gains in build time, reduced swap-in and -out rates, and a substantial reduction in swap readahead pages. The patch is based on measurements from various systems and configurations.

Ongoing Submitted 2026-10-30 🔥 TODAY [PATCH v2] mm/mempolicy: recompute automatic interleave weights on memory hotplug v1 → v2 Needs Work LLM (per-reviewer) Under Review

This patch addresses a performance regression caused by outdated automatic interleave weights in the Linux kernel's memory policy module (mm/mempolicy). When nodes gain or lose memory, their weights are not recalculated from their reported bandwidths, leading to an uneven distribution of data and potential overload. The patch introduces a new function, wi_state_refresh(), which recomputes the weights based on the recorded bandwidth whenever a node gains or loses its first/last memory. If allocating new weights fails, it warns once and continues with the next recompute starting from the full bandwidth table.

Needs Work LLM (per-reviewer) Under Review

This patch series addresses the issue of memcg stats flushing, which can be costly and introduce staleness in statistics. For the root memcg, it's possible to directly read global counters instead of going through rstat, as they are always up-to-date. The patches modify various call sites to use node counters for reading LRU sizes, working set, rotation, and reclaim writeback counts. The series consists of three patches: one fixes the zswap shrinker's count for the root memcg, another adds a function to read node counters for the root memcg, and the third modifies DAMON's quota goals to use node counters instead of flushing.

This patch adds a new function, `validate_mm_anon_rmap`, to the Linux kernel's memory management code. The function is responsible for verifying the consistency of anonymous memory mappings in a given VM area.
