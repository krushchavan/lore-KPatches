[PATCH v3 0/2] scsi: mpt3sas: Fix delayed not-responding sdev block handling 2 patches
Show 2 individual patches
  • [1/2] scsi: mpt3sas: Serialize interrupt-time sdev block with hostdata teardown
  • [2/2] scsi: mpt3sas: Time out delayed not-responding device blocks
Neutral llm-chunked-no-replies Awaiting Review

This patch series addresses a deadlock issue in the mpt3sas SCSI driver, which occurs when handling delayed not-responding devices (dnr). The problem is caused by a race condition between interrupt-time blocking and timed unblocking of sdevs. To fix this, the patches introduce serialization mechanisms to prevent concurrent access to shared data structures, including the use of locks and delayed work queues. Specifically, the patches modify the scsih_sdev_init() function to publish sdev->hostdata under a lock, clear block_deadline on all affected sdevs before TUR polling starts, and take the ioc->block_lock in _scsih_block_io_all_device(). Additionally, dnr_unblock_work is deferred while scsi_host_in_recovery(), and mod_delayed_work() is used for retrying. The patches aim to break the deadlock by unblocking sdevs after a timeout, ensuring that the driver can recover from delayed not-responding devices without causing further issues.

Ongoing Submitted 2026-10-29 🔥 TODAY [PATCH v2] mm: move LRU size stat updates out of lru_lock in folio batches Needs Work LLM (per-reviewer) Under Review

This patch moves the updates of LRU size statistics out of the lru_lock critical section in folio batches, which reduces contention and improves throughput. The stats are accumulated while holding the lock and applied after dropping it, reducing the overhead of cache misses and improving performance. This change is particularly beneficial for workloads with many threads faulting and freeing memory in a single memcg, where the hold time of lru_lock directly limits throughput. The patch also moves cost_lock into the hole after lru_lock to make room for the batch pointer, keeping struct lruvec from growing. The stats may lag behind the LRU lists by one batch, but this is within the per-cpu batching already present.

[PATCH] mm/memory: refuse to map page cache folios that are not uptodate Neutral llm-chunked-no-replies Awaiting Review

This patch prevents the Linux kernel from mapping page cache folios that are not uptodate, which can leak stale memory to userspace. The patch adds a function `file_folio_not_uptodate` to check if a folio is uptodate and refuses the mapping if it's not. This change affects the `finish_fault` and `do_set_pmd` functions in the kernel's memory management code. The goal of this patch is to prevent silent leaks of stale memory, which can occur when userspace maps page cache folios that have not been properly read in or cleared.
