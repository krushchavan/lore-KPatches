[PATCH] btrfs: downgrade the reflink source inode lock Neutral llm-chunked-no-replies Awaiting Review

This patch downgrades the lock on the source inode during reflink operations from exclusive to shared, reducing latency for concurrent readers. The change also adds a new flag to indicate when an inode is being used as a reflink source, which allows dio writes to take the VFS inode lock in shared mode instead of exclusive. This improves performance by avoiding unnecessary blocking of other shared lock users of the src file.

Needs Work LLM (per-reviewer) Under Review

This patch series adds a new flag to the KVM guest memory file descriptor (memfd) API, allowing users to bind the backing memory of the guest to a specific NUMA node. This is done by creating an MPOL_BIND policy for the requested node and installing it over the whole inode, ensuring that every folio is allocated on the specified node without requiring user-space mbind(). The patch series also includes self-test harness support and testing to validate the new functionality. The approach taken is to simplify the guest NUMA topology by binding a single fd to a host node, rather than interleaving it across multiple nodes, which would defeat placement decisions made by the guest.

Neutral llm-chunked-no-replies Awaiting Review

This patch addresses an issue where the ACPI RTC alarm handling in the Linux kernel's cmos driver can stop delivering events prematurely due to a race condition between the SCI handler and dispatch queues. The fix involves moving the clear and disable operations before dispatching the RTC interrupt, ensuring that rearming of alarms always wins the race. Additionally, the patch honors an explicit parameter value for using ACPI alarm handling, preventing automatic platform selection from overriding it.

  • [3/5] mm: keep the mmap dirty range down to the faulting page Submitted 2026-09-03
  • [4/5] iomap: narrow page_mkwrite() dirtying to the faulting page Submitted 2026-09-03
  • [5/5] xfs: track mmap dirty state per block Submitted 2026-09-03
Needs Work LLM (per-reviewer) RFC

This patch set introduces sub-folio dirty tracking for PTE-mapped mmap writes, addressing the issue of large page cache folios being dirtied unnecessarily when a single byte is written through a shared file mapping. The problem arises because current implementations mark the entire folio as dirty, leading to inefficient writeback and increased minor fault counts. To solve this, the patch harvests hardware PTE dirty bits at page_mkwrite() time and provides the filesystem with the ranges that were actually modified, allowing for more targeted writeback. This approach is already implemented in XFS and is shown to reduce writeback by 99% on a large file system.
