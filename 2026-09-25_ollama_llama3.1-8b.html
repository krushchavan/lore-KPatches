Ongoing Submitted 2026-09-12 🔥 TODAY [PATCH] proc/task_mmu: handle special PMDs in clear_refs and pagemap Needs Work LLM (per-reviewer) Under Review

This patch fixes a bug in the Linux kernel's /proc/PID/pagemap and /proc/PID/clear_refs functionality. The issue arises when a special PMD (Page Map Directory) is installed from a PFN (Physical Frame Number) that does not have a corresponding memmap entry. This causes the kernel to oops when trying to read or write these mappings. To fix this, the patch uses vm_normal_folio_pmd and vm_normal_page_pmd functions instead of pmd_folio and page_folio in certain paths, allowing the kernel to handle special PMDs correctly. The patch has been tested on QEMU with a test driver and has been reported to resolve the issue.

Needs Work LLM (per-reviewer) Under Review

This patch series addresses poor NUMA balancing behavior in a production deployment by modifying the VMA scan filters to no longer gate memory-tier promotion. The issue arises from the global balancing mode not being able to describe the intent of individual VMA/PTE walks, leading to unproductive socket-placement faults that prevent promotion. The patches introduce promotion-only NUMA protection walks and derive private VMA state in the folio eligibility check, allowing eligible shared folios to be promoted to a fast tier. Additionally, the patches separate VMA placement eligibility from partial-scan continuation and scan PID-inactive VMAs for promotion. The changes improve DRAM bandwidth, reduce CXL bandwidth saturation, and decrease request latency.

🔥 TODAY Re: Path forward for Virtualized Swap? Needs Work LLM (per-reviewer) Under Review

This patch proposes to allow virtualized swap to be treated as a separate tier from storage-backed swap, similar to how memory tiering works in the system. The idea is to reduce overhead by allowing compressed memory to stay mapped while read-only, thus avoiding faults and improving performance. This approach is inspired by zsmalloc's existing tiering concept and aims to address the issue of 'ghost-pressure' caused by software-compressed data requiring faults. The patch also clarifies that virtualized swap should be considered a physical resource, not just a logical one, aligning with historical definitions and usage.

This patch series addresses memory regressions caused by enabling 2M THP=always on arm64 with 64k base pages. The patches split underused anonymous mTHP folios, which are not currently reclaimed under memory pressure. Patch 1 makes the thp_underused() function size-aware to accommodate larger folio sizes. The patches aim to provide a solution for deploying 2M THP=always on arm64 without causing memory regressions.

🔥 TODAY [PATCH v7 0/2] iommu/arm-smmu-v3: Make the queue depths tunable, and shrink them in a kdump kernel 2 patches
Show 2 individual patches
  • [1/2] iommu/arm-smmu-v3: Add a cmdq_max_n_shift module parameter 🔥 TODAYNeutralUnder Review Nicolin Chen
  • [2/2] iommu/arm-smmu-v3: Default queue depths to one page in a kdump kernel 🔥 TODAYNeutralUnder Review Breno Leitao Nicolin Chen
Positive LLM (per-reviewer) Under Review

This patch series makes the queue depths in the ARM SMMUv3 IOMMU tunable, allowing them to be adjusted based on system requirements. The queues are currently sized from the IDR1 maximum and allocated at probe, which can consume megabytes of memory per queue per SMMU instance. In a kdump kernel, this can lead to out-of-memory errors due to limited crashkernel reservations. The patch series introduces a module parameter cmdq_max_n_shift that allows the command queue depth to be adjusted, and applies it in non-kdump kernels. This reduces the memory consumption of the queues from megabytes to kilobytes, allowing kdump kernels to save vmcores successfully.

Needs Work LLM (per-reviewer) Accepted

This patch optimizes the AMD uncore perf driver by removing redundant searches for counter slots in the amd_uncore_add() and amd_uncore_del() functions. The driver's serialization of event additions and deletions, combined with its inability to move events between slots, makes these searches unnecessary. By directly accessing the recorded slot index, the patch reduces CPU time spent on these functions from O(N^2) to O(N), where N is the number of counters in the PMU.

This patch optimizes the default comparison function in the Linux kernel's rhashtable module by utilizing compile-time constants when possible, reducing the need for dynamic memory access and improving performance. The patch achieves this by passing constant parameters from the caller to the comparison function, allowing it to use scalar comparisons instead of the generic memcmp() function. This change is expected to improve performance in various areas of the kernel, including scheduling, networking, and file systems.
