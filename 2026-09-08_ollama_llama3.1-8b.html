  • [3/3] mm: zswap: drop cold writeback folios via swap dropbehind 🔥 TODAYNeeds WorkUnder Review Submitted 2026-08-25 Yosry Ahmed Alexandre Ghiti Kunwu Chan
Needs Work LLM (per-reviewer) Accepted

This patch series improves the performance of zswap by promptly freeing cold writeback folios instead of leaving them on the LRU for page reclaim to find and free later. The existing dropbehind mechanism is extended to swap cache folios, allowing zswap to opt into it. This change reduces memory residency and waste in reclaim scans. Patch 1 moves LRU insertion out of the swap cache allocator, patch 2 drops dropbehind swap cache folios on writeback completion, and patch 3 enables zswap to allocate its writeback folio off the LRU and mark it as dropbehind.

  • [2/2] iommu/arm-smmu-v3: Default queue depths to one page in a kdump kernel PositiveUnder Review Submitted 2026-09-07Last comment 2026-09-07 Nicolin Chen
Needs Work LLM (per-reviewer) Under Review

This patch series makes the queue depths in the ARM SMMUv3 driver tunable, allowing users to adjust them based on their system's needs. The default queue depth is set to one page for a kdump kernel, which reduces memory usage and helps prevent out-of-memory errors during crashes. A new module parameter called cmdq_max_entries allows users to specify the maximum number of entries in each queue. This patch series also includes measurements showing that reducing the queue depths from 4KB to 1KB results in significant memory savings without impacting system performance.

[PATCH v2] mm/huge_memory: add folio_reset_partially_mapped() v1 → v2 Neutral llm-chunked-no-replies Awaiting Review

This patch adds a new function called folio_reset_partially_mapped() to the Linux kernel's huge_memory module. The function is responsible for resetting the PG_partially_mapped flag and updating the MTHP_STAT_NR_ANON_PARTIALLY_MAPPED stat when a folio is partially mapped. The patch extracts this common logic from two existing functions, __folio_unqueue_deferred_split() and __folio_freeze_and_split_unmapped(), to improve code organization and maintainability. The function asserts that the folio is frozen before performing these operations, ensuring that deferred split cannot set the flag again under it. This change aims to simplify the code and make it more efficient.
