Needs Work LLM (per-reviewer) Under Review

This patch series improves the performance of zswap by allowing it to free cold writeback folios promptly on completion, rather than leaving them for page reclaim. The existing dropbehind mechanism is extended to swap cache folios and zswap is made to opt into this mechanism. This change reduces the number of pages scanned during reclaim and keeps cold memory resident for shorter periods. The patch series includes three patches that move LRU insertion out of the swap cache allocator, implement dropbehind for swap cache folios, and modify zswap to allocate its writeback folio off the LRU and mark it as dropbehind.

Ongoing Submitted 2026-07-27 🔥 TODAY [PATCH v3] btrfs: trigger cow fixup via dirty_folio() v1 → v2 → v3 Neutral LLM (per-reviewer) Under Review

This patch reintroduces a fixup mechanism to handle a specific scenario where a dio read operation sees a dirty destination page, but by the time it finishes reading, the page is clean due to btrfs writing it back. The fixup ensures that the dio read re-dirties the folio to prevent data corruption. This patch addresses an issue that was previously thought to be resolved with advances in preventing such re-dirtying, and reintroduces a mechanism that was first introduced in 2008.

Needs Work LLM (per-reviewer) Accepted

This patch series converts the iomap code to use an iterator model, replacing the current begin/end pair of callbacks with a single next callback. This change allows for improved performance by enabling inlining and devirtualization of the iteration loop, as well as providing more flexibility for future callers to express custom logic in the IO path. The patches are broken down into 21 steps, including refactoring existing code, adding the new next callback, converting each filesystem, removing legacy paths, and updating documentation.
