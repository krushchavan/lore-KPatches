Ongoing Submitted 2026-09-03 🔥 TODAY [PATCH v3] mm/memcontrol: skip non-hierarchical memcg-wide stats when v1 is unavailable Positive LLM (per-reviewer) Under Review

This patch optimizes the Linux kernel's memory control group (memcg) statistics by skipping non-hierarchical memcg-wide stats when the v1 version is unavailable. This is done by compiling out the non-hierarchical arrays if CONFIG_MEMCG_V1 is not set, and skipping updates on these arrays even if v1 is supported but blocked by a boot parameter. The patch aims to reduce flush costs by avoiding unnecessary read-modify-write operations, resulting in a 4.1% reduction in memcg-wide aggregation time and a 2.2% reduction in overall flush function time.

This patch series moves the per-cpu 'stock' from mem_cgroup to page_counter, allowing for more efficient and independent stock management. [PATCH 08/12] mm/collapse: separate scanning a PTE table from collapsing it Neutral llm-chunked-no-replies Awaiting Review

This patch separates the scanning of a PTE table from collapsing it into two distinct functions: collapse_scan_pmd() and collapse_run_pmd(). The scan function reads the PTE table under mmap_lock and decides whether to collapse, while the run function performs the actual collapse. This change improves code organization and allows for better tracing and communication between the scan and run phases.

[PATCH 10/12] mm/collapse: work out the orders a VMA allows once per VMA Neutral llm-chunked-no-replies Awaiting Review

This patch optimizes the calculation of allowed page orders in a VMA by computing it once per VMA instead of once per PTE table. This is done to reduce redundant work and improve performance. The patch also introduces a new parameter, `enabled_orders`, which is passed from the caller to the function that computes the allowed orders. This change allows for more efficient handling of hugepage-enabled knobs written during a walk.

[PATCH 11/12] mm/collapse: declare the collapse interface in collapse.h Neutral llm-chunked-no-replies Awaiting Review

This patch declares the collapse interface in collapse.h, which includes functions and variables related to memory collapsing. The interface consists of four main calls: collapse_control_init, collapse_scan_pmd, collapse_run_pmd, and collapse_control_release. These functions are used for collapsing large pages and are currently static in khugepaged.c. The patch also renames hugepage_vma_revalidate to collapse_vma_revalidate as it is now part of the collapse interface. This change prepares the ground for implementing MADV_COLLAPSE in madvise.c, but does not introduce any functional changes.
