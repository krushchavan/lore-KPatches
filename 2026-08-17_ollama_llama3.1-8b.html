[PATCH v1 0/2] mm: fix workingset refaults in the zswap writeback path 2 patches
Show 2 individual patches
  • [1/2] mm/swap: refault on swap-in, not in the swap cache allocator
  • [2/2] mm/zswap: preserve the workingset shadow across writeback
Neutral llm-chunked-no-replies Awaiting Review

This patch series addresses two issues in the zswap writeback path that cause incorrect workingset refaults. The first issue is over-counting at writeback, where a buffer folio allocated by the shrinker is counted as a refault. The second issue is lost eviction cookies at reclaim, where the original cookie is overwritten when adding the buffer to the swap cache. To fix these issues, the patch preserves the shadow within zswap itself and moves the refault evaluation out of the swap-cache allocator into the swap-in callers. This results in a significant reduction (-48% to -59%) in workingset refaults, activations, and restores, with no impact on throughput.

Contentious LLM (per-reviewer) Accepted

This patchset replaces khugepaged's anonymous collapse mechanism with a new engine that can collapse sub-PMD ranges, built around migration entries and frozen folios to improve scalability and reduce disruption to the workload being collapsed. The old mechanism held the address space still by locking it, while the new engine makes the sources themselves inert between two barriers, allowing the copy to run without holding any lock. This change aims to fix limitations in the original implementation, particularly with PMD-granular operations and VMA alignment.

[PATCH] memcg: trim the per-cpu charge stock instead of draining it Neutral llm-chunked-no-replies Awaiting Review

This patch modifies the per-cpu charge stock in Linux's memory cgroup (memcg) to trim excess pages instead of draining them completely when a watermark is reached. This change aims to improve performance by reducing thrashing caused by frequent emptying and refilling of the cache, which occurs due to a specific pattern of write and read system calls on the same CPU. The patch introduces two new watermarks (MEMCG_STOCK_LOW and MEMCG_STOCK_HIGH) that are used to determine when to trim the cache, allowing for more efficient use of memory resources.
