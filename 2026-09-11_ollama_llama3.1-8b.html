[PATCH v4 0/3] mm: fix workingset refaults in the zswap writeback path 3 patches
Show 3 individual patches
  • [1/3] mm: swap: move LRU insertion out of the swap cache allocator
  • [2/3] mm: swap: refault on swap-in, not in the swap cache allocator
  • [3/3] mm: zswap: preserve the workingset shadow across writeback
Neutral llm-chunked-no-replies Awaiting Review

This patch fixes two issues in the zswap writeback path that cause incorrect workingset refaults. The first issue is over-counting at writeback, where a buffer folio allocated by the shrinker is counted as a refault. The second issue is lost eviction cookies at reclaim, where the original cookie is overwritten when adding the buffer to the swap cache. To fix these issues, the patch preserves the shadow within zswap itself and moves the refault evaluation out of the swap-cache allocator into the swap-in callers. This results in a significant reduction (-48% to -59%) in workingset refaults, activations, and restores for anonymous pages.

[PATCH v5 0/3] mm: zswap: free cold writeback folios promptly 3 patches
Show 3 individual patches
  • [1/3] mm: swap: move LRU insertion out of the swap cache allocator
  • [2/3] mm: swap: drop dropbehind swap cache folios on writeback completion
  • [3/3] mm: zswap: drop cold writeback folios via swap dropbehind
Neutral llm-chunked-no-replies Awaiting Review

This patch series optimizes zswap by promptly freeing cold writeback folios instead of leaving them for page reclaim to find and free later, which wastes a reclaim scan and keeps cold memory resident longer than necessary. The existing dropbehind mechanism is extended to swap cache folios, and zswap is modified to opt into this mechanism. Patch 1 moves LRU insertion out of the swap cache allocator, patch 2 drops dropbehind swap cache folios on writeback completion, and patch 3 allocates the writeback folio off the LRU and marks it dropbehind.

🔥 TODAY [PATCH v2 1/3] btrfs: pre-flush reflink source before taking inode locks Needs Work LLM (per-reviewer) Under Review

This patch optimizes the reflink operation in Btrfs by pre-flushing the source file's dirty pages before taking inode locks, reducing contention between writers and readers. This is done through a single backwards pass that waits for ordered extents on the inode without locking the ordered tree. The approach taken avoids consistency errors associated with concurrent writes and allows for a common case optimization without significant infrastructure investment.

[PATCH v2 2/3] btrfs: skip unlocked reflink source flush if the inode has writers Neutral llm-chunked-no-replies Awaiting Review

This patch modifies the btrfs reflink code to skip optimistic unlocked flushing if there are active writers dirtying pages, as it can result in doubly writing back pages that get dirtied again before a locked flush. The change is advisory and does not guarantee against extra writeback, but helps in simple cases with long open file descriptors or mappings.

[PATCH v2 3/3] btrfs: downgrade the reflink source inode lock for tree walking Neutral llm-chunked-no-replies Awaiting Review

This patch modifies the behavior of reflink in Btrfs to downgrade the lock on the source inode from exclusive to shared during tree walking, reducing contention between reflinks and other file operations. The patch addresses two issues related to direct I/O: it adds a flag to prevent direct I/O writes from taking the lock shared when the source inode is being used as a reflink source, and it ensures that direct I/O reads do not block reflinks by remaining exclusive until after finishing with inode_dio_wait().

This patch series separates the collapse engine from its callers in the Linux kernel's memory management code.
