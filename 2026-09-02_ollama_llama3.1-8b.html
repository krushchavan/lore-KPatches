Show 5 individual patches

  • [2/5] mm/mempolicy: add mpol_set_shared_policy_range()
  • [3/5] KVM: guest_memfd: bind backing memory to a NUMA node at creation
  • [4/5] selftests: KVM: guest_memfd: let the gmem_test() harness bind a node
  • [5/5] selftests: KVM: guest_memfd: test GUEST_MEMFD_FLAG_BIND_NODE
Neutral llm-chunked-no-replies Awaiting Review

This patch series introduces a new flag, GUEST_MEMFD_FLAG_BIND_NODE, to the KVM guest memory file descriptor (memfd) API. When set, this flag binds the backing memory of the memfd to a specific NUMA node, ensuring that all allocated folios are placed on that node. This is done by creating an MPOL_BIND policy for the requested node and installing it over the whole inode. The patch series includes preparatory work in the mm/mempolicy code, as well as selftest harness support and testing. The approach taken is to bind each fd to a single host node, rather than allowing interleaving across multiple nodes, which would defeat guest NUMA balancing decisions.

Needs Work LLM (per-reviewer) Under Review

This patch eliminates unnecessary copies of nodemask and node weights in the interleave paths of the Linux kernel's memory policy module. It achieves this by using SRCU to pin node weights in place, operating directly on pol->nodes for nodemasks, and clamping the walk to a single pass. The changes improve performance but may introduce a small trade-off in distribution accuracy during rebind operations.

🔥 TODAY [PATCH v2] mm/memcontrol: skip non-hierarchical memcg-wide stats on the default hierarchy Needs Work LLM (per-reviewer) Under Review

This patch optimizes memory control group (memcg) statistics by skipping non-hierarchical memcg-wide stats on the default hierarchy, reducing flush costs and improving performance. The optimization is based on the observation that only legacy memory.stat and memory.numa_stat readers access these stats, which are not used on the default hierarchy. By skipping these stats, the patch reduces cacheline accesses and improves flush function performance by 2.2%. The change also includes a mechanism to handle cases where a controller is moved from the default hierarchy to the legacy v1 hierarchy at runtime.
