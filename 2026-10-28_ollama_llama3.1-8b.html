This patch reduces cacheline contention between lruvec stat updates and LRU lists by rearranging the layout of struct mem_cgroup_per_node to pair read-mostly lines with cold lines, and modifying folio and kmem stat updates to avoid going through the lruvec. This change improves performance on systems that use spatial prefetching, such as Intel CPUs. The patch includes two changes: one that reorders the fields in struct mem_cgroup_per_node, and another that modifies the stat update functions to skip using the lruvec. The results show a significant improvement in pages per second for threads faulting in and freeing memory in a single memcg.

🔥 TODAY Re: [PATCH v8 5/8] fuse: {io-uring} Allow reduced queues through INIT negotiation Contentious LLM (per-reviewer) Under Review

This patch consolidates the logic for creating and updating the mapping of queues to CPU IDs in the FUSE (Filesystem in Userspace) implementation of io-uring. The current approach has two separate flows for legacy and dynamic queue paths, which are merged into a single flow. In this new flow, the mapping is updated on the first registration of a queue, and it's built from the global registered queue mask. This change also fixes an issue where requests mapped to a queue could get lost if there was a failure between adding the queue and registering its first entry. Additionally, the patch allows dynamic queues to be advertised, which enables rejecting qids that don't map to possible CPU IDs during ADD_QUEUE.
