[PATCH v2] NFS: don't wait for writeback on close() with a write delegation v1 → v2 Needs Work llm-chunked-no-replies Awaiting Review

This patch modifies the NFS (Network File System) kernel code to no longer wait for writeback on close() when a write delegation is held. The previous behavior, introduced by commit 5445b1fbd123, caused servers that send a limit of 0 to not benefit from write delegations, even though they are granted by the server. The patch reverts this change and instead uses filemap_flush() for non-blocking writeback on close(). This resolves issues with error reporting and allows applications to rely on fsync() for flushing data to disk. The patch also removes unused code related to pagemod_limit.

Ongoing Submitted 2026-11-19 🔥 TODAY [PATCH] mm/memory: don't map hardware-poisoned pages in finish_fault() Positive LLM (per-reviewer) Under Review

This patch prevents hardware-poisoned pages from being mapped in the page cache when a large file folio cannot be split by memory_failure(). Instead, it maps each poisoned page individually, allowing it to take its own fault and resulting in a SIGBUS signal. This change addresses an issue where a process touching a poisoned page would instead receive a machine check. The patch builds upon existing functionality in finish_fault() and is designed to prevent the mapping of hardware-poisoned pages when using large file folios.

Needs Work LLM (per-reviewer) Under Review

This patch series improves the performance of slow GUP (get user pages) by batching whole PTE tables and reducing the number of refcount grabs. The current implementation resolves and commits one PTE per call, leading to a restart of the page table descent and re-taking of the PTE lock for every page. This patch series brings the slow path in line with the fast path, which already batches PTE-mapped large folios. The patches include refactors, helper functions, and changes to follow_page_pte() and gup_lookup_pte(). The result is a significant performance improvement, with median get times reduced by up to 12.8x for mTHP (large memory pages) and 2.3x for base pages.

Needs Work LLM (per-reviewer) Accepted

This patch series addresses a performance issue in the Linux kernel's kernfs subsystem by reducing unnecessary locking during mkdir and rmdir operations. The current implementation holds multiple locks, including kernfs_iattr_rwsem, which can lead to host-wide stalls under memory and CPU pressure. The patches remove the write lock on kernfs_iattr_rwsem for these operations, as it is not necessary for most cases. Instead, other mechanisms such as seqlocks and inode setup are used to ensure consistency. As a result, mkdir and rmdir latency is significantly reduced, with improvements in both VM and physical host environments. The patches also improve the performance of stat() and access() operations on paths with iattrs.

Needs Work LLM (per-reviewer) Under Review

This patch series fixes two bugs in the Linux kernel's perf/core module related to software event sample data. The first bug, present since v6.3, occurs when a sampling event inherits an uninitialized sample ID and timestamp from a previous event, causing issues with concurrent 'perf record' sessions. The second bug, introduced in v6.1, allows BPF programs to read uninitialized stack contents through the bpf_perf_event_data::addr field. The patches initialize the struct for each matching event, prevent BPF programs from reading uninitialized data, and stop zero-initializing the struct in do_perf_sw_event(). These changes improve performance by reducing the time it takes to handle context switches.
