This patch series addresses a performance issue in NUMA balancing by separating promotion-only scans from socket-placement scans. The current implementation prevents hot memory in read-only file mappings and VMAs without recent PID activity from being promoted to a faster tier, leading to increased request latencies. The patches introduce a new protection flag (MM_CP_PROT_NUMA_PROMO_ONLY) that allows for promotion-only scans, enabling eligible shared folios to be promoted and reducing the impact of filters on memory-tier promotion. This change improves performance by allowing hot memory to be moved to faster tiers, resulting in increased bandwidth usage and reduced request latencies.

Needs Work LLM (per-reviewer) Under Review

This patch series moves the per-CPU cache of pre-charged pages, known as 'stock', from mem_cgroup to page_counter. This change is necessary to make future page_counters scalable and performant, particularly in scenarios where multiple new page_counters are introduced to a memcg. The existing seven-slot per-CPU design and drain policy are retained. For memcg v1 users, this decouples the memory and memsw stocks, potentially leading to different sizes of precharged cache for each. To prevent an invariant from being broken, the patch reports the larger value of memory and memsw usage_in_bytes for memsw reporting.
