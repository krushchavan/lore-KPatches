[PATCH 6.18.y] fs/proc/task_mmu: fix PAGEMAP_SCAN written state for unpopulated ptes Neutral llm-chunked-no-replies Awaiting Review

This patch fixes a bug in the PAGEMAP_SCAN functionality of the Linux kernel's /proc/task_mmu interface. The issue arises when an unpopulated page table entry (pte) is encountered, and its written state is reported differently depending on whether the fast path or the generic path is taken. To fix this, the patch reports pte_none as written in both paths, ensuring consistency and preventing issues with incremental-dump consumers like CRIU. A selftest has been added to verify the correctness of the change.

[PATCH 6.18.y] mm/huge_memory: unlock i_mmap_rwsem before releasing after-split folios Neutral llm-chunked-no-replies Awaiting Review

This patch fixes a use-after-free bug in the Linux kernel's huge memory handling code. The issue occurs when splitting a transparent huge page (THP) that has been poisoned by memory failure, causing the inode to be evicted before the i_mmap_rwsem is unlocked. To fix this, the patch moves the unlock of i_mmap_rwsem to after the remap_page() call, ensuring that all mapping dereferences occur while the folio still pins the inode. This change establishes a new rule for the split function: no inode or mapping dereference should occur once the after-split folios start being unlocked.

[PATCH 6.18.y] mm/hugetlb: fix swap entry corruption when clearing uffd-wp at fork() Neutral llm-chunked-no-replies Awaiting Review

This patch fixes a bug in the Linux kernel's huge page handling code that caused corruption of swap entries when clearing the uffd-wp bit during fork(). The issue arose because the present-PTE bit position was being used to clear the uffd-wp bit, but the swap entries kept the state elsewhere. This led to incorrect updates of the swap offset, which could cause problems later on. The patch fixes this by using the correct function to clear the uffd-wp bit in swap entries and removing the unnecessary clearing of hwpoison entries.

This patch modifies the futex_wait_setup function to read the futex word before taking the hash bucket lock, reducing contention and improving performance. The change allows for a precheck of the futex value without acquiring the lock, which is particularly beneficial in scenarios where the futex words are frequently mismatched. This approach also simplifies the code by removing unnecessary lock acquisitions and waiter accounting operations. By avoiding hash-bucket locking for mismatched waits, the patch aims to reduce contention and improve overall system performance.

Needs Work LLM (per-reviewer) Superseded

This patch series introduces PMD-level swap entries for anonymous THPs, allowing huge mappings to survive the swap round-trip without needing khugepaged to collapse the range later. The PMD swap entry is a compact page-table encoding for HPAGE_PMD_NR consecutive swap slots and does not promise that the swap cache always contains one PMD-sized folio. When reclaim swaps out a PMD-mapped anonymous THP, it can now restore the PMD mapping directly on swap-in without waiting for khugepaged to collapse the range later. The series includes 11 patches that add support for PMD swap entry detection, splitting, and handling in various paths such as fork, zswap, and swap. This change aims to improve performance by reducing the overhead of split-THP and khugepaged.
