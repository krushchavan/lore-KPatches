Ongoing Submitted 2026-10-27 🔥 TODAY [PATCH RFC fstests] generic: add a test for multigrain timestamps Needs Work LLM (per-reviewer) Under Review

This patch adds a test to ensure that multigrain timestamps are working correctly in Linux kernels. The test, called 'mgtime', checks that the mtime and ctime of a file appear to change even when there are multiple writes in quick succession. This is particularly important for filesystems like ext4, f2fs, btrfs, tmpfs, and xfs, which support multigrain timestamps but may not be universally supported on all filesystems. The test uses a loop to write to a file 1000 times and then checks that the mtime and ctime are different from the previous value each time. If the values do not change, the test fails.

[PATCH] statx: add STATX_ATTR_MULTIGRAIN_TIMESTAMP Neutral llm-chunked-no-replies Awaiting Review

This patch adds a new attribute to the statx system call, STATX_ATTR_MULTIGRAIN_TIMESTAMP, which indicates whether a file's timestamps are multigrain. This allows userland applications to determine if successive changes after a query will yield distinct timestamps. The attribute is set in vfs_getattr_nosec() when the inode has IOP_MGTIME set, and it is always advertised in attributes_mask. This patch addresses a limitation in the current statx system call where there was no way for userland to determine if a file's timestamps were multigrain.
