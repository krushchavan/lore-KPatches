[PATCH] btrfs: fix double release of data space on failed direct IO COW write Neutral llm-chunked-no-replies Awaiting Review

This patch fixes a double release of data space on failed direct IO copy-on-write (COW) writes in the Btrfs file system. The issue occurs when a COW write fails after reserving data space, causing the reserved extent to be freed and then releasing all allocated data space again. This results in an underflow of available data space, leading to warnings and clamping to zero. The patch records the consumed length during reservation and releases only the remaining allocated data space on error, preventing the double release and fixing the issue.

Ongoing Submitted 2026-11-09 🔥 TODAY [PATCH v1] mm/rmap: fix migration entries being treated as partial unmaps Needs Work LLM (per-reviewer) Superseded

This patch fixes an issue where migration entries in the Linux kernel are being treated as partial unmaps, leading to incorrect behavior such as unnecessary folio splits and overcounting of split_deferred statistics. The problem occurs when a large anonymous folio is migrated or split, causing the PG_partially_mapped flag to be set even though no actual unmapping has taken place. To fix this, the patch introduces a new flag that prevents __folio_remove_rmap() from marking a folio as partially mapped when migration entries are replaced for PTEs. This ensures that only actual unmappings trigger the deferred split queue and corrects the statistics. The patch also addresses issues related to migrated folios being queued for unnecessary splits and overcounting of split_deferred statistics.

Ongoing Submitted 2026-11-12 🔥 TODAY [PATCH v3] mm/page_alloc: only skip kswapd nodes below their kswapd watermark v2 → v3 Needs Work LLM (per-reviewer) Accepted

This patch modifies the behavior of get_page_from_freelist() to only skip nodes with kswapd running if they are below their relevant low-memory watermark. This change is intended to prevent unnecessary pressure on already-pressured remote nodes in NUMA systems, where kswapd can be woken up for reasons other than creating free space. The patch was tested on a 2-NUMA VM and showed improved performance by directing faults to the node with available memory. It addresses an issue introduced by commit 19c5fb83f2a4 and is suggested by Daniel Hodges, reviewed by several developers, and signed off by Joshua Hahn.
