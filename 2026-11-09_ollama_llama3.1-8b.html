Needs Work LLM (per-reviewer) Accepted

This patch addresses a performance regression in the Linux kernel, specifically related to swap I/O operations on synchronous devices like NVMe partitions. The issue arises from two commits: one that prefers non-full clusters over free ones and another that frees swap slots on exclusive write faults. This leads to scattered writes and increased read requests, resulting in decreased throughput. The patch proposes a solution by only preferring non-full clusters on synchronous devices, which improves performance metrics such as device read and write requests per transaction and throughput.

Neutral llm-chunked-no-replies Awaiting Review

This patch series addresses a deadlock issue in the mpt3sas SCSI driver, which occurs when handling delayed not-responding devices (dnr). The problem is caused by a race condition between interrupt-time blocking and timed unblocking of sdevs. To fix this, the patches introduce serialization mechanisms to prevent concurrent access to shared data structures, including the use of locks and delayed work queues. Specifically, the patches modify the scsih_sdev_init() function to publish sdev->hostdata under a lock, clear block_deadline on all affected sdevs before TUR polling starts, and take the ioc->block_lock in _scsih_block_io_all_device(). Additionally, dnr_unblock_work is deferred while scsi_host_in_recovery(), and mod_delayed_work() is used for retrying. The patches aim to break the deadlock by unblocking sdevs after a timeout, ensuring that the driver can recover from delayed not-responding devices without causing further issues.

This patch fixes a bug in the Linux kernel's memory management system where migration entries are being treated as partial unmaps, leading to incorrect behavior and statistics. When migrating or splitting large anonymous folios mapped by PTEs, the kernel incorrectly marks them as partially mapped, causing issues with deferred splits, statistics, and folio splitting. The patch introduces a flag to prevent this incorrect marking for migration entries, ensuring that only actual unmappings are treated as such.

This patch series proposes a change to how Linux handles page cache reads, allowing multiple CPUs to read from the same folio without taking a reference. This is done by introducing a new flag PG_rcu_free and deferring the freeing of folios until an RCU grace period. The goal is to reduce contention between readers and improve performance in scenarios where many threads are reading the same pages. The patch series includes 18 patches that implement this change, including modifications to filemap_read(), shmem, and other related functions.
