[PATCH v3 0/3] mm: zswap: free cold writeback folios promptly 3 patches
Show 3 individual patches
  • [1/3] mm: swap: move LRU insertion out of the swap cache allocator
  • [2/3] mm: swap: drop dropbehind swap cache folios on writeback completion
  • [3/3] mm: zswap: drop cold writeback folios via swap dropbehind
Neutral llm-chunked-no-replies Awaiting Review

This patch series improves memory management for zswap by freeing cold writeback folios promptly, rather than leaving them on the LRU for page reclaim to find and free later. It achieves this by extending the existing dropbehind mechanism to swap cache folios and having zswap opt into it. The patches move LRU insertion out of the swap cache allocator, drop dropbehind swap cache folios on writeback completion, and modify zswap to allocate its writeback folio off the LRU and mark it dropbehind. This reduces memory waste and keeps cold memory resident for a shorter period.

Ongoing Submitted 2026-08-06 🔥 TODAY memcg stats flushing (WAS "Re: [PATCH] fuse: disable default bdi strictlimiting") Needs Work LLM (per-reviewer) Changes Requested

This patch addresses the issue of stale memory cgroup (memcg) stats causing premature OOM kills by proposing a solution to reduce the overhead of updating and flushing these statistics. The idea is for memcg to accumulate updates on a per-CPU basis, then propagate them up to a global atomic counter when it reaches a certain threshold, eliminating the need for frequent flushing. This approach aims to scale better for large machines with many cores and focuses on reducing the number of stats that require flushing, specifically NR_FILE_DIRTY and NR_WRITEBACK in the writeback case.

Needs Work LLM (per-reviewer) RFC

This patch introduces a new boot parameter 'cgroup.memory=tiered_limits' that enables tier-proportional scaling and enforcement of memory cgroup controller limits. The feature is incompatible with cgroup v1 and raises a warning if a system booted with tiered limits mounts a legacy cgroup. A static key is used to minimize overhead for cgroups not using tier-aware memcg limits, which will become a hotpath in later commits.

Contentious LLM (per-reviewer) Accepted

This patchset replaces khugepaged's anonymous collapse mechanism with a new engine that can collapse sub-PMD ranges, built around migration entries and frozen folios to improve scalability and reduce disruption to the workload being collapsed. The old mechanism held the address space still by locking it, while the new engine makes the sources themselves inert between two barriers, allowing the copy to run without holding any lock. This change aims to fix limitations in the original implementation, particularly with PMD-granular operations and VMA alignment.

This patch series improves the coverage of selftests/mm by adding new cases to test the khugepaged mechanism, which collapses huge pages into smaller ones. The existing tests were limited and did not cover all possible scenarios. The new additions include folio-order helpers, anon collapse cases with mixed sources, a shared-source write race, and tests for various edge cases such as faults, MADV_DONTNEED, pins, fork, mremap, reclaim, compaction, and KASAN/lockdep checks. The changes also address existing issues in the test suite, including scaling the collapse wait time with PMD size, skipping certain cases where they are not applicable, and retrying swap cases to ensure accurate results.
